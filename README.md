# AI動画編集ツール

撮影素材をこのツールに通すと、次のどちらかが手に入ります。

- **荒編集**（`roughcut.py`）：Premiere Proで開くと、カット済み・字幕付きの状態から作業を始められる
- **完成動画**（`finish.py`）：テロップ・ズーム・BGM・効果音・字幕まで入った、そのまま投稿できる動画

| やること | 中身 |
|---|---|
| 文字起こし | faster-whisper（large-v3-turbo）をGPUで実行 |
| 無音カット | 喋っていない所を詰める（ジャンルで強さを変える） |
| **言い直し・NGの除去** | Claudeが文脈を読んで「失敗テイク」「段取りの会話」を判定 |
| 字幕 | 編集後のタイミングに合わせたSRT。AIが誤認識も直す |
| マーカー | 見どころ★／要確認／早送り候補（無言の作業）など |
| 2台目カメラ | 音声で自動同期して、同じカットでV2に配置 |
| 投稿用の情報 | タイトル案・概要欄・チャプター・サムネ文字・タグ |
| **仕上げ** | AIが強調テロップ・ズーム・BGM・効果音を決めて、完成動画まで書き出す |

## 1. セットアップ（最初の1回だけ）

### かんたんセットアップ（おすすめ）
1. zipを展開して、`ai-roughcut` フォルダを `C:\tools\ai-roughcut` に置きます
   - 展開すると `ai-roughcut\ai-roughcut` と二重になることがあります。**`setup.bat` が入っている方のフォルダ**を `C:\tools` に置いてください
   - デスクトップや「ドキュメント」（OneDrive）は避けてください
2. フォルダの中の **`setup.bat` をダブルクリック**します
   - Python・FFmpeg・必要なライブラリのインストール、動作確認まで全部自動で進みます（初回は20〜30分）
   - 「WindowsによってPCが保護されました」と出たら、「詳細情報」→「実行」を押してください
3. 終わると、**デスクトップとスタートメニューに「AI動画編集」のアイコン**ができます。次からはこれをダブルクリックするだけで起動します
4. 起動したら、画面の「APIキーを設定…」で Claude の APIキーを入れます（claude.ai に貼り付けて使う場合は不要）

ツールを新しい版に入れ替えたときも、ファイルを上書きしてから `setup.bat` をもう一度実行すれば更新されます。

### 手動でセットアップする場合
かんたんセットアップがうまくいかないときは、次の手順で1つずつ進めてください。

### 1-1. Python と FFmpeg を入れる
PowerShell を開いて実行します。
```powershell
winget install Python.Python.3.12
winget install Gyan.FFmpeg
```
入れ終わったら、**PowerShellを一度閉じて開き直します**。

### 1-2. ツールのフォルダで必要なものを入れる

#### ① zipを展開して、置き場所を決める
zipを展開してできた `ai-roughcut` フォルダを、たとえば `C:\tools\ai-roughcut` に置きます。

- **デスクトップや「ドキュメント」は避けてください**。OneDriveで同期されていることが多く、この後に入れる約2GBのライブラリまで同期されてしまいます
- フォルダのパスに日本語やスペースが入らない場所のほうが、トラブルが起きにくいです（**素材ファイルのパスは日本語でも大丈夫**です）

#### ② そのフォルダでPowerShellを開く
エクスプローラーで `ai-roughcut` フォルダを開き、上のアドレスバーに `powershell` と入力して Enter を押すと、そのフォルダでPowerShellが開きます。
別の場所で開いた場合は、`cd` で移動します。
```powershell
cd C:\tools\ai-roughcut
```
`ls` を実行して、`roughcut.py` や `requirements.txt` が表示されれば、正しい場所にいます。

#### ③ このツール専用のPython環境（仮想環境）を作る
仮想環境とは、このツール用のライブラリをPC全体と分けて入れておく箱のようなものです。他のPythonの作業に影響しません。
```powershell
py -3.12 -m venv .venv
```
フォルダの中に `.venv` というフォルダができれば成功です。

> `py` が見つからないと言われたら、1-1のあとにPowerShellを開き直したか確認してください。それでもだめなら `python -m venv .venv` を試してください。

#### ④ 仮想環境を有効にする
```powershell
.venv\Scripts\activate
```
行の先頭に **`(.venv)`** と表示されれば有効になっています。

> **「このシステムではスクリプトの実行が無効になっているため…」と赤いエラーが出た場合**
> Windowsの初期設定で、スクリプトの実行が止められています。次のコマンドを1回だけ実行し、確認が出たら `Y` を押してから、もう一度 `.venv\Scripts\activate` を実行してください。
> ```powershell
> Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
> ```

#### ⑤ ライブラリを入れる
```powershell
python -m pip install --upgrade pip
pip install -r requirements.txt
```
GPUで動かすためのNVIDIAライブラリ（cuBLAS / cuDNN）も一緒に入るので、**合計で約2.5GBのダウンロード**になります。回線によっては10分ほどかかります。
最後に `Successfully installed ...` と出れば完了です。

#### ⑥ 正しく入ったか確認する
次の3つを順に実行します。
```powershell

```
```powershell

```
```powershell
python -c "import faster_whisper, anthropic; print('OK')"
```

|---|---|---|

| `nvidia-smi` | 表に `NVIDIA GeForce RTX 5050` が出る | NVIDIAのドライバーを最新にする（GeForce Experience / NVIDIA App から） |
| `python -c ...` | `OK` | `(.venv)` が付いているか確認して、⑤をやり直す |

#### 2回目以降は
PowerShellを開いたら、毎回 **②と④だけ** やれば使えます（`cd` でフォルダに移動して、`.venv\Scripts\activate` を実行）。
`roughcut_drop.bat` に動画ファイルをドラッグ＆ドロップする方法なら、この操作も要りません。

> 初めて `roughcut.py` を実行したときに、文字起こしモデル（約1.6GB）が自動でダウンロードされます。2回目以降はダウンロードされません。

### 1-3. Claude との連携（どれか1つ）
AIの判定（カット・演出・タイトルなど）に Claude を使う方法は3つあります。「作成」タブの **AI** の欄で選びます。

| 方法 | 料金 | 準備 |
|---|---|---|
| **Claude で自動（サブスク・Claude Code）** おすすめ | サブスク（Pro / Max）の範囲。追加の料金なし | Claude Code を入れてログイン（下記） |
| Claude APIで自動（従量課金） | 使った分だけ（素材30分で数十円ほど） | APIキー（下記） |
| claude.ai に貼り付けて使う | サブスクの範囲 | なし（途中でコピー＆貼り付け） |

**サブスク（Claude Code）で使う準備**（最初の1回だけ）
1. PowerShell を開いて、次を実行します（Claude Code のインストール）
   ```powershell
   irm https://claude.ai/install.ps1 | iex
   ```
2. PowerShell を開き直して `claude` と入力し、表示に従って **サブスクのアカウント（claude.ai と同じ）でログイン**します。ログインできたら `/exit` で閉じます
3. ツールを起動し、AIの欄で「Claude で自動（サブスク・Claude Code）」を選んで「接続を確認」を押します。「✔ 接続できました」と出れば準備完了です

- ツールは裏で `claude -p`（1回だけ質問して答えをもらう使い方）を呼びます。動画や音声は送らず、文字起こしの文字と、必要なときだけ静止画を数枚送ります
- サブスクの使用量の上限（数時間ごとの枠）に入ります。3時間の素材を何本もまとめて処理すると上限に届くことがあり、そのときは「上限に達しました」と出て止まります（時間をおいて同じボタンを押せば、やり直せます。文字起こしはやり直さないので、AIの判定の所からです）
- APIキーを設定していても、この方法のときは使いません（API料金がかからないように、Claude Code にはキーを渡しません）
- 使うモデルを決めたいときは、環境変数 `ROUGHCUT_CC_MODEL`（例: `opus`）。空なら Claude Code の設定のままです

**APIキーで使う場合**
[Claude Console](https://platform.claude.com/) でAPIキーを作り、設定します。
```powershell
setx ANTHROPIC_API_KEY "sk-ant-..."
```
設定したら、PowerShellを開き直します。
APIを使わずに、claude.ai に貼り付けて判定する方法もあります（後述の `--llm manual`）。

## 2. 画面（GUI）で使う

デスクトップの **「AI動画編集」アイコンをダブルクリック**すると、ツールの画面が開きます（アイコンがない場合は、フォルダの中の `start_gui.bat` でも起動できます）。

### 「作成」タブ
1. **素材**：動画ファイルを枠の中にドラッグ＆ドロップします。カメラが分割したファイルは全部入れます。2台目カメラ（スマホなど）があれば、下の枠に入れます
2. **撮影ジャンル**：レビュー・解説／工作／屋外企画 から選びます
3. **設定**
   - AI：「Claude で自動（サブスク・Claude Code）」なら「接続を確認」で準備ができているか確かめられます（準備は 1-3）。「Claude APIで自動」なら「APIキーを設定…」で一度キーを入れておきます。「claude.ai に貼り付けて使う」を選ぶと、途中でコピー＆貼り付けの画面が出ます
   - AIへの指示（任意）：AIに言葉で伝えたいことを書きます。例「工具の説明は全部残して」「テンポ重視で短めに」「テロップは少なめで、ツッコミ多め」。カットの判定・演出プラン・タイトル作りなど、AIが関わるすべての所で使われます
   - 見た目テンプレート：「見た目を確認」で、字幕やテロップの見本を作れます
   - 固有名詞：商品名や人名を「、」区切りで入れると、字幕の精度が上がります
   - 保存先：結果（`○○_roughcut` フォルダ）を作る場所です。はじめは「素材と同じ場所」（今まで通り）です。「選ぶ…」でフォルダを選ぶと、その中に作ります。選んだ場所は次回も使います。下に、実際に作るフォルダが出ます
     - カメラのファイル名（`C0001.MP4` など）は撮影ごとに同じなので、別の撮影の同じ名前の結果がもうあるときは、`C0001_2_roughcut` のように番号を付けて分けます（前の結果は上書きしません）。同じ素材をもう一度荒編集したときは、同じフォルダを使います
     - 外付けドライブを外していて保存先が見つからないときは、お知らせが出て止まります。「素材と同じ場所に戻す」で元に戻せます
     - 「まとめて処理」に入れた動画も、同じ保存先に作ります
4. **荒編集する**（確認しながら進めたいとき）または **完成まで一気に作る** を押します

下の帯に、いま何をしているかと進み具合が出ます。「ログを表示」で詳しい表示も見られます。

### 「確認・仕上げ」タブ
荒編集が終わると、自動でこのタブに切り替わります。

**① カットの確認**
- AIがカットした発言（赤）、要確認（黄）、見どころ（緑）が一覧で出ます
- 行をクリックすると、右側でその場面を再生します
- **「使う」のチェックを外すとカット、付けると残します**
- 字幕の文字は、ダブルクリックで直せます
- 直したら「カットの変更を反映」を押します（文字起こしはやり直さないので、すぐ終わります）
- Premiereで仕上げたいときは「Premiere用XMLを開く」

**② 演出の確認**
- 「演出プランを作る」を押すと、AIが決めたテロップ・ズーム・BGMが一覧で出ます
- テロップの文字、種類、効果音、BGMの雰囲気を変えたり、チェックを外して取り消したりできます
- 「最初の60秒を試し書き出し」で雰囲気を確認してから、「完成動画を書き出す」を押します

**言葉で指示してやり直す**（「AIへの指示」の欄）
- 結果を見て直してほしい所を書き、ボタンを押します
  - 「**この指示でカットをやり直す**」：文字起こしはそのままで、AIがカットを判定し直します（例「3分あたりの工具の話は残して」「言い直しはもっと積極的に切って」）。表で手直ししたカットは、新しい判定に置き換わります
  - 「**この指示で演出を直す**」：今の演出プラン（表での手直しも含む）を元に、指示に沿ってAIが直します（例「テロップをもっと派手に」「後半のBGMは明るめに」「ズームは控えめ」）。指示に関係ない所はなるべくそのままです
- 何度でも繰り返せます。「作成」タブの「AIへの指示」もいっしょに使われます
- 「claude.ai に貼り付けて使う」のときは、貼り付け用のプロンプトに指示と今の演出が入ります

前に作った結果は、「別の結果を開く…」で `○○_roughcut` フォルダを選べば、いつでも開き直せます。

## 3. コマンドで使う

```powershell
.venv\Scripts\activate
python roughcut.py "D:\撮影\レビュー.mp4" --mode talk
```

### モード（撮影ジャンル）
| `--mode` | 向いている動画 | 動き |
|---|---|---|
| `talk`（初期値） | レビュー・解説 | 無音を積極的に詰め、AIのカットを適用する |
| `craft` | 工作 | 喋りの間は詰めるが、**4秒以上の無言区間（作業シーン）は残して**「早送り候補」マーカーを付ける |
| `outdoor` | 屋外企画 | **自動ではカットしない**。NG候補や見どころをマーカーで示すだけ（`--apply-ai-cuts` を付けるとカットも適用） |

### よく使う例
```powershell
# カメラが自動分割したファイルは、順番に並べると1本の素材として扱います
python roughcut.py C0001.MP4 C0002.MP4 C0003.MP4 --mode outdoor

# 工作：カメラとスマホの2台撮り（スマホは音声で自動同期してV2へ）
python roughcut.py 正面.MP4 --mode craft --cam2 手元スマホ.mp4

# 固有名詞リストを渡すと、文字起こしと字幕の精度が上がります
python roughcut.py レビュー.mp4 --glossary words.txt
```
`words.txt` は1行に1語です（例: `マキタ`、`インパクトドライバー`、`Qpic`）。

### APIを使わない方法（claude.ai に貼り付ける）
```powershell
python roughcut.py 素材.mp4 --llm manual
```
1. 出力フォルダの `prompt_cuts.md` の中身を claude.ai に貼り付けます
2. 返ってきた返答を `claude_cuts.json` として保存します（```json などが付いたままでも大丈夫です）
3. 判定を指定して、もう一度実行します（文字起こしは前回の結果を再利用するので、すぐ終わります）
   ```powershell
   python roughcut.py 素材.mp4 --llm manual --decisions 素材_roughcut\claude_cuts.json
   ```
4. タイトル等も欲しい場合は、`prompt_youtube.md` で同じ手順を踏み、返答を `--meta` で指定します

## 4. Premiere Pro での読み込み

1. **ファイル → 読み込み** で `○○_荒編集.xml` を選ぶと、カット済みのシーケンスができます
2. `○○_字幕.srt` も読み込み、タイムラインにドラッグするとキャプショントラックになります
3. マーカー（M）で、見どころや要確認の箇所に飛べます
4. 2台目カメラは **V2トラック（初期状態は非表示）** に入っています。目のアイコンで表示を切り替えてください

> 荒編集なので、最後は自分の目で確認してください。カットの一覧と理由は `report.md` にまとめてあります。

## 5. 仕上げ（完成動画まで自動で作る）

荒編集のあとに実行します。
```powershell
python finish.py "D:\撮影\レビュー_roughcut"
```
荒編集から一気に完成まで進めたいときは、`roughcut.py` に `--finish` を付けます。
```powershell
python roughcut.py "D:\撮影\レビュー.mp4" --mode talk --finish
```

### 仕上げでやること
1. **演出プラン**：Claudeが文字起こしを読んで、強調テロップ・ズーム・BGMの区間・効果音を決めます（`plan_used.json` に保存）
2. **本編の書き出し**：カットとズームを反映します（RTX 5050のNVENCで高速エンコード）
3. **音声**：BGMは喋っている間だけ自動で下がります。最後に、全体の音量をYouTube基準（-14 LUFS）にそろえます
4. **焼き込み**：字幕・テロップ・章タイトルのカード・ロゴを動画に焼き込みます

完成すると `○○_完成.mp4` ができます。章タイトルのカードは、荒編集で作ったチャプターの位置に出ます。

### よく使うオプション
| オプション | 内容 |
|---|---|
| `--preview 60` | 最初の60秒だけ書き出して確認する（数十秒で終わります） |
| `--plan plan_used.json` | 演出プランを手で直してから、書き出し直す（演出プランのAIは呼ばれません。書き出し後のサムネイル案は `--llm` に従います） |
| `--llm manual` | APIを使わず、claude.ai に貼るプロンプト（`prompt_plan.md`）を作る。返答を保存して `--plan` で指定 |
| `--llm none` | AIの演出なし（字幕とBGMだけ） |
| `--template フォルダ` | 別の見た目テンプレートを使う |

### 演出プランを手で直すには
`plan_used.json` をメモ帳などで開くと、次のように書かれています（数字は `chunks.json` の発言ID）。
```json
{"telops": [{"start_id": 12, "end_id": 13, "text": "重さ わずか1.2kg！", "style": "emphasis", "se": "pop"}],
 "zooms":  [{"id": 40, "strength": "medium"}],
 "bgm":    [{"start_id": 1, "mood": "upbeat"}, {"start_id": 85, "mood": "calm"}]}
```
不要なテロップの行を消したり、文字を直したりしてから `--plan plan_used.json` で書き出し直せます。

### 完成動画の一部（区間）だけを書き出す
SNS 用の切り抜きなど、完成動画の好きな所だけを 1本の動画にできます。

1. 完成動画を書き出したあと、「確認・仕上げ」タブの **「区間を書き出す…」** を押します
2. 開いた画面で完成動画を再生し、**「ここを開始に」「ここを終了に」** で区間を決めます
   - 開始・終了の欄に時刻を直接入れることもできます（`1:23`、`1:23.5`、`83`、`1分23秒` のどれでも。全角でも大丈夫です）
   - **「章」** から選ぶと、その章をまるごと区間にします
   - 「◀ 1秒」「1秒 ▶」で少しずつ動かせます。**「区間を再生」** で、決めた区間だけを確かめられます
3. **「書き出す」** を押すと、結果フォルダの `clips` に `○○_完成_1m23s-2m10s.mp4` ができます。「できた動画を再生」で確認できます

- コマ単位で正確に切るため、映像は作り直します（GPU があれば数秒〜数十秒です）。画質は見た目テンプレートの `[video]` の設定を使います
- 「字幕ファイル（SRT）も作る」にチェックがあると、区間に合わせて時刻をずらした字幕（同じ名前の `.srt`）も作ります。字幕は動画に焼き込まれているので、YouTube や SNS に字幕データも付けたいとき用です
- 一度に書き出すのは 1つの区間です。続けて別の区間を選んで「書き出す」を押せば、何本でも作れます。前に選んだ区間は、ツールを閉じるまで覚えています

コマンドで使う場合:
```powershell
python clip.py "D:\撮影\レビュー_roughcut" --start 1:23 --end 2:10   # 区間を書き出す
python clip.py "D:\撮影\レビュー_roughcut" --list                     # 章の一覧
python clip.py "D:\撮影\レビュー_roughcut" --chapter 2                # 2番目の章をまるごと
```
`--out ファイル名` で書き出し先を、`--no-srt` で字幕を作らないようにできます。結果フォルダの代わりに、完成動画のファイルを直接指定することもできます。

## 5-2. サムネイル案

完成動画を書き出すと、続けて**サムネイル案が9枚**自動で作られます（`○○_roughcut\thumbnails` フォルダ）。GUIでは「サムネイル案を見る」で一覧できます。

1. 候補の静止画を約20枚取り出します。見どころ・強調テロップ・ズームの場面は8枚までにして、残りは**完成動画の最初から最後まで均等に**取ります（話している途中の場面ばかりにならないように。ブレた画像は除きます）
2. Claude が候補の画像を実際に見て、サムネイル向きの3枚と、入れる文字を選びます（一覧で小さく見ても何の動画か分かる場面＝商品のアップ・手に取って見せている所・結果が見える所などを優先します）。商品名などの**小さな見出し**と、文字を置いても大事な所（顔・商品・表示）が隠れない**側**も一緒に決めます
3. 3枚それぞれを、3種類のデザイン（大きな文字／帯／横に文字）で合成します（1280×720、YouTubeの上限2MB以下）。文字は写真の空いている側（上か下、左か右）に置き、帯や線の色は写真から選びます

### 見せ方（テンプレートの `[thumbnail]` の `style`）
| `style` | 見た目 | 向いている動画 |
|---|---|---|
| `elegant`（上品・初期設定） | 明朝体の白い文字に柔らかい影。小さな金の見出しと線を添える | 文房具・工芸品・料理など、落ち着いた題材 |
| `pop`（ポップ） | 太いゴシック体の黄色い文字に、黒と白の二重のふち | ガジェット・検証・バラエティなど、目立たせたいとき |
| `simple`（シンプル） | 半透明の板の上に白いゴシック体 | 解説・まとめなど、すっきり見せたいとき |

- 画面では「作成」タブの「見た目テンプレート」の「編集…」→「サムネイル」タブの **「見せ方」** で選べます。見せ方を変えると、色は見せ方の色に戻ります
- 文字の色・縁取りの色・帯の色は、空なら見せ方の色です。`"#RRGGBB"` で決めると、そちらを使います。帯・線の色を `"auto"` にすると写真から選びます
- フォントは、空なら見せ方に合うものを Windows に入っているフォントから選びます（上品は Noto Serif JP → 游明朝、ポップ・シンプルは Noto Sans JP → 游ゴシック の順）
- 見出しは、YouTube のスマホの一覧くらい小さく表示されても読める大きさ（大きな文字の4割・54px以上）で入れます。長い見出しは縮め、それでも入らない分は「…」にします。上品の金の線は、ロゴなど大事な所に重なるときは引きません
- YouTube の一覧では、サムネイルの右下に動画の長さ（「12:34」など）が重ねて表示されます。文字・見出し・バッジは、この右下（横は右から約2割、縦は下から約15%）にかからないように置きます（下に置く文字は少し上げる、下の帯の文字は少し左に寄せる、横に文字・縦書きは右下を空ける）。AIにも、大事な所が右下に来る場面は避けるよう伝えています
- **文字は、写真の中の物（ペン・はかりの表示・ロゴなど）に重ならない所に置きます。** AIが「大事な所の枠」とは別に、特に隠してはいけない物を1つずつ囲み（`keep_boxes`、`thumbnails.json` にも残ります）、さらに枠の中の輪郭の多い所を物として扱います。箱の面や台などの平らな所には文字を置いてもよいことにしています
  - 物に少しでも触れる置き方は避け、置き場所が無いときは上下の間の高さに置いたり、文字を少し小さくしたりします（シンプルは文字の後ろの板も含めて判断します）
  - 横に文字・縦書きでは、写真を少し大きくして切り出す位置を何通りか試し、物が切れず・文字に重ならないものを選びます（基本は、写真の中身を文字の反対側へ寄せます）
- 文字を読みやすくするための影は、**画面の下半分・上半分・右半分・左半分のように、文字のある側を端までいっぱいに**かけ、反対側へなめらかに薄くします（文字のまわりだけ暗くして、中途半端に明るい所が残ることがありません）。影の濃さは**文字の後ろの明るさに合わせ**、白い紙の上なら白い文字が読める所まで、紺の箱の上などもともと暗い所ならごく薄くします（サムネイル全体が黒っぽくなりません）
- 強調して大きくした言葉の字（「30g」の g など、下に出る字）が次の行の字に重ならないよう、行の間は見た目の字の上下で空けます
- 帯の文字は、見た目（見出しの字の上から大きな文字の下まで）が帯の真ん中に来るようにします（明朝体でも下に寄って見えません）
- 小さな見出しが要らないときは `label = false` にします
- 前の版で作ったテンプレート（`style` が無いもの）は、今までと同じポップの見せ方になります

### デザインもAIに任せる（`art_director = true`・初期設定）
AIが案ごとに、文字だけでなく**デザインの組み合わせ**も決めます。決めた内容は「サムネイル案」画面の各案の下に「デザイン: …」と出ます。

| 表現 | 内容 |
|---|---|
| 強調する言葉 | 「30g」「2回」など、いちばん効く言葉だけを大きく・別の色にします（色は `emphasis_color`。空なら見せ方の色: 上品=金・ポップ=赤・シンプル=黄） |
| バッジ | 「限定」「検証」など4字くらいまでの札を、文字と主役に重ならない隅に置きます。上品=朱色の落款（縦書きのはんこ）、ポップ=ギザギザの星形、シンプル=角の丸い札（色は `badge_color`） |
| 縦書き（`vertical`） | 明朝体の縦書き。「ー」やかっこは縦向きに回し、「30g」のような短い英数字は縦中横にします。上品の見せ方に特に合います |
| 写真の効果 | `focus`=主役以外をぼかして暗くする / `sticker`=主役を切り抜いて白いフチ（上品は柔らかい光）を付ける / `depth`=主役を文字の手前に重ねる（雑誌の表紙のような奥行き） |
| 影の強さ（`shade`） | 文字の後ろの影を `light`=うすめ（写真の明るさを活かす。四隅の暗さも半分に）/ `normal` / `strong`=こいめ（文字をくっきり）。ふつう以外は「デザイン: 影うすめ（明るく）」のように出ます |

- 主役の切り抜きは、ダウンロード不要の OpenCV（GrabCut）で行います。**2つのやり方で切り抜いて、結果がほぼ一致したときだけ**使います。ふちがはっきりしない写真（白い紙の上の白い物など）では切り抜かず、`sticker` と `depth` は `focus`（主役の枠の外をぼかす）に切り替えます
- `focus`・`sticker` で主役のまわりを暗くするのは控えめにし、そのぶん四隅の暗さも弱めます（サムネイル全体が黒っぽくならないように）
- `depth` は、主役が大きな文字を1字でも3割5分より多く隠すとき、または小さな見出しに少しでも重なるときは、文字を手前のままにします（読めなくならないように）
- 見せ方の組み合わせ（`layouts`）も、写真に合うものをAIが3つ選びます（例: 縦長の空きがある写真なら縦書き）。実際に合成してみて、文字や帯が大事な所を隠しすぎるもの（ペンを覆ってしまう帯など）は、まだ使っていない見せ方に替えます
- AIを使わないとき（文字を自分で決めたときも）は、テンプレートの `layouts` のとおりに作り、文字に数字（「1.2kg」「2回」など）があればそれだけを強調します。バッジ・効果は付けません
- `art_director = false` にすると、今までどおり（強調・バッジ・効果なし、`layouts` のとおり）になります
- **AIの考える深さはサムネイルだけ別**に決められます（`[thumbnail]` の `effort`、初期設定は `high` = じっくり）。動画の編集を「ふつう」にしていても、サムネイル選びだけ深く考えさせられます。画面では「サムネイル」タブの「AIの考える深さ」で変えられます。コマンドでは `thumbs.py --effort low` のように、その回だけ変えることもできます

文字を自分で決めたいときは、GUIの一覧画面の下の欄に入力して「この文字で作り直す」を押します。コマンドなら次のとおりです。
```powershell
python thumbs.py "D:\撮影\レビュー_roughcut" --text "軽すぎ！\n本当に？"
```

### できたサムネイル案を見て、AIに指示する
「サムネイル案」画面の **「AIへの指示」** の欄に、直してほしいことを書いて **「AIに指示して作り直す」** を押します（Enter でも同じです）。AIが「Claude APIで自動」のときに使えます。

- 例: 「案2は文字を左に」「もっと明るく」「バッジは要らない」「真ん中の段の右端は別の場面で」「見出しを『野原工芸』に」
- AIには、**今の案の画像**（画面と同じ並びで、案1が上の段・各段は左から）と、それぞれの場面・文字・デザインを見せたうえで指示を伝えます。指示に関係ない所は、なるべく前の案のまま残します
- 指示は**積み重なります**（前の指示も守ったまま、次の指示を足せます）。反映ずみの指示は画面に「反映ずみの指示: …」と出ます（`thumbnails/requests.json`）。「別の場面から選び直す」「場面を選んで作り直す」「この文字で作り直す」で作り直すと、まっさらに戻ります
- 指示で作り直すときは、前と同じ候補の静止画を使い回します（取り出し直さないので速く、場面の番号もそろいます）
- コマンドなら次のとおりです
```powershell
python thumbs.py "D:\撮影\レビュー_roughcut" --request "案2は文字を左に。もっと明るく"
```

### 使う場面を自分で選ぶ・別の場面から選び直す
各案の見出しには、完成動画のどこの場面か（「案1（3:04）」など）が出ます。

- **「場面を選んで作り直す…」**：動画から取り出した場面が、完成動画の時刻の順に並びます。使いたい場面をクリックして選び（**3つまで**。選んだ順に①②③＝案1・案2・案3）、「選んだ場面で作る」を押します。右クリックで大きく開けます
  - 一覧に無い場面は、下の欄に**完成動画の時刻**で入れられます（例: `1:23, 4:56`）。クリックで選んだ場面の後に続きます
  - 選んだ場面には、AIが文字とデザインを付けます（AIなしなら、動画のタイトル案の文字で作ります）。選んだ場面が3つより少ないときは、残りをAI（AIなしなら自動）がほかの場面から選びます
  - **「ほかの場面も出す（＋20）」**：今の一覧とは別の所を、動画全体から20か所足します（サムネイル案は作り直しません。押すたびに増えます）
- **「別の場面から選び直す」**：今の案に使っている場面を外し、動画全体から新しく取り出した場面（取る位置も前回からずらします）から、AI（AIなしなら自動）が選び直します
- 場面の一覧は `thumbnails/candidates.json` と `thumbnails/_candidates` に残ります。カットや早送りを変えたら、次に作るときに取り出し直します
- コマンドなら次のとおりです
```powershell
python thumbs.py "D:\撮影\レビュー_roughcut" --scenes "1:23, 4:56"   # 使う場面（完成動画の時刻。3つまで）
python thumbs.py "D:\撮影\レビュー_roughcut" --fresh                 # 別の場面から選び直す
python thumbs.py "D:\撮影\レビュー_roughcut" --more-scenes           # 場面の一覧を増やす
```

## 5-3. YouTubeへの投稿

GUIの「確認・仕上げ」タブで **「YouTubeへ」** を押すと、投稿用の画面が開きます。タイトル（AIの候補から選択）・概要欄（チャプター付き）・タグ・カテゴリ・サムネイルを確認・修正できます。

### おすすめの流れ（Googleの審査なしで使える）
1. 「① YouTube Studio を開く」→ 完成動画をドラッグ＆ドロップ（公開設定は**非公開のまま**でOK）
2. 「② アップした動画に設定を反映」→ ツールが今アップした動画を見つけて、タイトル・概要欄・タグ・カテゴリ・サムネイルを一括で設定します
3. Studio で確認して、公開（または予約公開）します

> **動画ファイルそのものをAPIでアップロードしない理由**：Googleの審査（audit）を通していない個人のプロジェクトからAPIでアップロードした動画は、YouTubeの仕様で「非公開」にロックされ、公開できなくなります。アップロード済みの動画へのタイトル・サムネイル等の設定は、審査なしでできます。審査を通した場合は「APIで動画ごとアップロード」も使えます。

Googleとの連携をしない場合も、「タイトルをコピー」「概要欄をコピー」「タグをコピー」で Studio に貼り付けられます。

### YouTube連携の準備（最初の1回だけ・15分ほど）
Google Cloud の画面の名前は時々変わるので、見つからない場合は近い名前の項目を探してください。

1. [Google Cloud Console](https://console.cloud.google.com/) に、YouTubeチャンネルのGoogleアカウントでログインし、**新しいプロジェクト**を作ります（名前は例：`ai-video-editor`）
2. 「APIとサービス」→「ライブラリ」で **YouTube Data API v3** を検索して「有効にする」
3. 「OAuth 同意画面」（Google Auth Platform）を設定します
   - ユーザーの種類：**外部**
   - アプリ名・サポートメール：自分の名前とGmailでOK
   - **テストユーザー**：自分のGmailアドレスを追加
4. 「認証情報」→「認証情報を作成」→「OAuth クライアント ID」→ アプリケーションの種類 **「デスクトップ アプリ」** → 作成して **JSONをダウンロード**
5. ツールの「YouTubeへ」画面で「連携の準備（client_secret.json）…」→ ダウンロードしたJSONを選ぶ
6. 「Googleアカウントと連携」→ ブラウザで許可します
   - 「このアプリは Google で確認されていません」と出たら、「詳細」→「（アプリ名）に移動」で進めます（自分で作ったアプリなので問題ありません）

> **7日ごとに連携が切れる場合**：OAuth 同意画面の公開ステータスが「テスト」のままだと、Googleの仕様で7日ごとに再ログインが必要です。「アプリを公開」で「本番環境」にすると解消します（自分だけで使う分には、Googleの確認審査を受けなくても使えます）。

## 6. 見た目のテンプレート（チャンネルの刷新はここで）

見た目はすべて `templates/default/template.toml` で決めています。初期状態は、Windowsに標準で入っている「BIZ UDPゴシック」を使った、シンプルな見た目です。

| 項目 | 内容 |
|---|---|
| `[caption]` | 画面下の字幕（フォント・大きさ・色・縁取り・1枚の最大文字数） |
| `[telop.emphasis]` など | 強調・補足・注意・ツッコミの4種類のテロップ（位置・色・出方のアニメーション） |
| `[chapter_card]` | 章タイトルのカード |
| `[zoom]` | ズームの強さ |
| `[thumbnail]` | サムネイルの見せ方（上品・ポップ・シンプル）・文字の色・フォント・デザインの種類（5-2 を参照） |
| `[intro]` `[outro]` `[logo]` | オープニング・エンディング動画、ロゴ画像（空なら使わない） |
| `[audio]` | 音量の基準、BGM・効果音の音量、BGMを下げる強さ |

### 見た目だけを確認する
```powershell
python finish.py --template-preview
```
8秒のサンプル動画と静止画3枚が、テンプレートのフォルダにできます。色やフォントを変えたら、これで何度でも確認できます。自分の素材を背景にしたい場合は `--sample 素材.mp4` を付けます。

### 新しいデザインを作るとき
1. `templates/default` フォルダをコピーして、`templates/新チャンネル` のような名前にします
2. 使いたいフォントの `.ttf` / `.otf` を、その中の `fonts` フォルダに入れます（無料で使える例：Noto Sans JP、M PLUS Rounded 1c、Zen Maru Gothic など。Google Fontsで配布されています）
3. `template.toml` の `font = "..."` を、そのフォントの名前に書き換えます
4. `--template templates\新チャンネル` を付けて実行します

### BGMと効果音
- **BGM**：`bgm/calm`（落ち着いた）、`bgm/upbeat`（明るい）、`bgm/tension`（緊張感）、`bgm/emotional`（しんみり）のフォルダに曲を入れます。AIは、曲が入っている雰囲気の中から選びます。曲はYouTube Studioの「オーディオライブラリ」などから入手できます。**収益化やクレジット表記の条件は、曲ごとに必ず確認してください**
- **効果音**：`se` フォルダに `pop` `ding` `whoosh` `boing` の4種類が入っています（このツール用に合成した音なので、自由に使えます）。同じ名前のファイルで差し替えれば、好きな音に変えられます

### いっしょに使うときの注意（初期設定で変わること）
- **声の処理は初期設定で使います**（`[audio_clean]` の `enabled = true`）。前のバージョンで書き出した完成動画と比べると、声の音が少し変わります。音楽が主役の動画では `enabled = false` にしてください
- **屋外モードでは手ブレ補正も初期設定で使います**（`[stabilize]` の `enabled = "auto"`）。書き出しの時間は長くなります
- **2台目カメラがある素材**では、演出プランを作るときに手元カメラの場面も自動で決まります（`[multicam]` の `auto = false` で止められます）
- **工作モード**では、喋っていない作業の場面が自動で早送りになります（`[speedup]` の `enabled = false` で止められます）。早送りの場面が手元カメラの場面と重なると、手元カメラの映像を早送りで使います。Bロール・字幕・テロップ・チャプター・章の進み具合は、早送りで短くなったあとの時刻に合わせます
- 手ブレ補正・色の補正をしていても、途中で止まった書き出しは、できているところから続けます
- 「公開後の分析」は、YouTube連携に「視聴維持率を読む許可」を足します。前からの連携のままでもアップロードはできます。分析を使うときだけ「分析」タブで連携し直してください

### 企画・台本づくりと撮り漏れチェック
撮影の前に、Claude と一緒に「何を話して、何を撮るか」を決めておき、撮影のあとで話し忘れ・撮り忘れを確かめられます。

**① 企画を作る（「企画」タブ）**
1. 「テーマ」（例: マキタの新しいドリルをレビュー）を入れ、「ジャンル」（レビュー・解説／工作／屋外企画／MV／そのほか）と「長さの目安」を選びます。伝えたいことや使う道具があれば「メモ」に書きます
2. 「構成案・台本・撮影リストを作る」を押すと、次の3つができます
   - **構成**：オープニングから締めまでの流れと、それぞれの目安の長さ
   - **台本（話す要点）**：読み上げる原稿ではなく、話し忘れを防ぐための短いメモ。★は必ず話すこと
   - **撮影リスト**：正面・手元・Bロール・挿入カットに分けた「撮るもの」と撮り方のコツ
3. 表の中はダブルクリックで直せます。「行を追加」「選んだ行を消す」で増やしたり減らしたりして、「保存」を押します。構成（見出し）の名前を変えると、その名前で分け直します
4. 「印刷用ページを開く」でブラウザが開くので、Ctrl+P で紙や PDF にして撮影に持っていけます（チェック欄つき）

- AIは「作成」タブの設定を使います。「claude.ai に貼り付けて使う」ならコピー＆貼り付けの画面が出ます。「AIを使わない」ならジャンルの定番の流れのひな形を作るので、自分で書き込んで使えます
- 企画はツールのフォルダの `projects\<企画の名前>\` に、`plan.json`（中身）・`plan.md`（メモ用）・`plan.html`（印刷用）として保存されます
- 「確かめる言葉」は、撮り漏れチェックで「話したか」を調べるための言葉です。表記ゆれは `重さ|おもさ` のように「|」で区切ります。空のときは、要点の文から自動で選びます

**② 撮り漏れチェック（「確認・仕上げ」タブの「③ 撮り漏れチェック」）**
1. 荒編集が終わったら、「台本（企画）」で撮影に使った企画を選びます（次からは自動で選ばれます）
2. **照合する**：「確かめる言葉」が文字起こしに出てくるかで調べます（AIなし・すぐ終わる・無料）
   **AIで詳しく照合**：Claude が文字起こしを読んで、言い回しが違っても話したかどうかを判断します
3. 話していない要点・一部だけの要点・**話したけれどカットした要点**・撮った記録がないカットが、赤や黄色で出ます。行をクリックすると、その場面を右側で再生します
4. カットは、文字起こしからは「撮れているか」が分からないことが多いので、撮れていたら「状態」に印を付けてください（企画の撮影リストの「撮った」にも記録されます）

結果は荒編集のフォルダの `preprod_check.md`（一覧）と `preprod_check.json` に保存されます。

**コマンドで使う場合**
```powershell
python preprod.py new "本棚を作る" --genre craft --minutes 12 --notes "SPF材と電動ドリル"   # 企画を作る（Claude API）
python preprod.py new "本棚を作る" --genre craft --llm manual    # claude.ai に貼るプロンプトを作る
python preprod.py new --name 本棚を作る --answer 返答.txt          # claude.ai の返答を取り込む
python preprod.py list                                             # 企画の一覧
python preprod.py export 本棚を作る                                 # plan.json を手で直したあと、印刷用を作り直す
python preprod.py check 素材_roughcut --project 本棚を作る           # 撮り漏れチェック（言葉の一致）
python preprod.py check 素材_roughcut --llm api                     # Claude で照合（2回目からは --project を省略できます）
```

### 全動画の発言検索（「素材検索」タブ）
「あの動画で〇〇の話をしたのはどこだっけ？」を、全部の動画をまたいで探せます。

1. 「探すフォルダ」に、動画を保存しているフォルダ（例: `D:\YouTube`）を選びます。「作成」タブで保存先を選んでいるときは、その保存先のフォルダを選んでください
2. 「索引を更新」を押すと、その中にある `○○_roughcut` フォルダの文字起こしを全部読み込みます。2回目からは、新しく荒編集した動画や字幕を直した動画だけを読み直すので、すぐ終わります。消した動画は索引から外します
3. 言葉を入れて「検索」（Enter キーでも）。空白で区切ると、全部の言葉を含む発言を探します（例: `マキタ 重さ`）
4. 結果をクリックすると、右側でその場面を再生します。**ダブルクリック**（または「「確認・仕上げ」で開く」）で、その動画の荒編集を「確認・仕上げ」タブで開き、その発言を選んだ状態にします

- カタカナとひらがな（ドリル／どりる）、全角と半角（ＳＰＦ／SPF）の違いは気にせず探せます。字幕を直した発言は、直した後の文で探します
- 荒編集でカットした発言は、ふだんは出しません。「カットした発言も含める」にチェックを入れると、［カット済み］の印付きで出ます（撮ったけれど使わなかった話を探すときに便利です）
- 索引はツールのフォルダの `search_index.sqlite` に保存します。3時間の素材が何本あっても、1本ずつ読み込むのでメモリは少しで済みます
- 元の素材を別の場所に移したときは、もう一度「索引を更新」を押してください

**コマンドで使う場合**
```powershell
python search.py index "D:\YouTube"          # 索引を作る・更新する
python search.py find ドリル                  # 全動画から探す
python search.py find "マキタ 重さ" --include-cut   # 両方を含む発言。カットした発言も探す
python search.py list                        # 索引に入っている動画の一覧
```

### タイムライン表示と画面のデザイン（ダークモード・使い方の案内）
**タイムライン（「確認・仕上げ」タブの上）**
- 音の波形の上に、編集の様子を色の帯で表示します
  - **残す**：青い波形 ／ **カット**：赤い斜線の帯（波形は灰色）／ **要確認**：黄色 ／ **見どころ**：緑 ／ **章**：紫の見出し
- **クリック**：その場所から右のプレーヤーで再生し、下の一覧の行も選びます。逆に一覧の行を選ぶと、タイムラインのその場所に枠が付きます（「② 演出の確認」の行でも同じです）
- **ダブルクリック**（または右クリック →「この発言をカットする／残す」）：その発言の「残す／カット」を切り替えます。一覧の「使う」のチェックと同じなので、最後に「カットの変更を反映」を押してください（押し忘れがないよう、ボタンがオレンジの枠になります）
- **拡大・縮小**：マウスのホイール、または右上の虫めがねボタン。「全体を表示」ボタンで元に戻ります。**移動**：ドラッグ、または下のスクロールバー（タッチパッドの横スクロールも使えます）
- 赤い縦線は、いま再生している位置です。マウスを乗せると、その場所の時刻・発言・カットの理由が出ます
- 波形は、初めて開いたときに FFmpeg で音だけを軽く取り出して作り、`○○_roughcut\waveform_cache\` に保存します（3時間の素材でも 約0.5MB。2回目からはすぐに出ます）。作っている間も、ほかの操作はそのまま続けられます
- いらないときは「表示」メニューの「タイムラインを表示」のチェックを外すと隠せます

**画面の見た目**
- 右上の「ダーク／ライト」ボタンで、暗い画面（ダークモード）と明るい画面を切り替えられます。選んだ設定は保存され、次に開いたときもそのままです
- 「表示」メニュー →「画面の明るさ」で「Windowsの設定に合わせる」（はじめはこれ）・「ライト」・「ダーク」を、「文字の大きさ」で「標準・大きめ・特大」を選べます
- 大事なボタンほど目立つ色にしました（青：完成動画を書き出す・完成まで一気に作る、赤：YouTubeへ）。よく使うボタンにはアイコンが付きます

**使い方の案内**
- 初めて開いたときは、「作成」タブの上に 4つのステップの案内が出ます。「わかった（次から表示しない）」で消えます（右の × は今回だけ閉じます）
- あとから見たいときは、右上の「使い方」ボタン、または「表示」メニューの「使い方の案内」で、もう一度表示できます
- この機能は `gui_ext_timeline.py`（画面）・`rc_waveform.py`（波形の取り出し）・`rc_theme.py`（色とアイコン）に入っています。テスト：`python tests/test_timeline.py`（`tests/smoke_test.py` からも呼ばれます）

### 2台カメラの自動切り替え
カメラ＋スマホの2台で撮ったとき（荒編集で「2台目カメラ」の欄に入れた／`--cam2` を付けたとき）、場面ごとにどちらのカメラの映像を使うかを決めて、完成動画で自動で切り替えます。

- **決め方**：喋っているときは正面（本編）カメラ。長い無言の作業（初期値 4秒以上）や、「ここを」「この部品」「こうやって」など手元を指す言葉のある発言は、手元（2台目）カメラにします
- **最短ショット長**：1つのカメラを続けて映す長さは、カット後の動画で**3秒以上**にそろえます（短い切り替えは前後とまとめます）。2台目の映像がない所（撮り始める前など）は正面のままです
- **音声は正面カメラのまま**：切り替わるのは映像だけです。2台目が縦長のスマホ動画のときは、同じ映像をぼかした背景で左右を埋めます
- **いつ決まるか**：「演出プランを作る」（コマンドでは `finish.py`）のときに自動で決まり、演出プランの `angles` に**元の素材の時刻**で保存されます。あとでカットを変えても同じ場面を指します

#### 画面での確認・変更
「② 演出の確認」に **「カメラ」** の表が出ます（2台目があるときだけ）。
- 行をクリックすると、その場面を再生し、下に**正面と手元の静止画**を並べて表示します
- 「使う」のチェックを外すと正面のまま。開始・終了の時刻はダブルクリックで直せます（例: `1:23.5`）
- 「＋ 追加」で再生中の位置から5秒の場面を足せます。「選んだ行を削除」で消せます
- **自動で選び直す**：上のルールで選び直します
- **AIで選び直す**：Claude に**両カメラの静止画と発言**を見せて、場面ごとに決めてもらいます（Claude API を使います。目安: 10分の動画で20円ほど）
- 変更は、ほかの演出の手直しと同じく `plan_edited.json` に保存され、「試し書き出し」「完成動画を書き出す」に使われます

#### Premiere Pro では
`○○_荒編集.xml` の V2 トラックに2台目の映像が並び、**手元カメラを選んだ区間のクリップだけ有効**（それ以外は無効＝非表示）になります。縦長のスマホ映像は画面の高さに収まる大きさにしてあります（左右には V1 の正面カメラが見えます。ぼかし背景は Premiere では付きません）。演出プランを作る前の XML は、今まで通り V2 トラックごと非表示です。

#### コマンドで使う
```powershell
# 自動（AIなし）で選び直す
python multicam.py "D:\撮影\工作_roughcut"
# Claude に静止画と発言を見せて選ぶ
python multicam.py "D:\撮影\工作_roughcut" --llm api
# 今の設定を表示するだけ
python multicam.py "D:\撮影\工作_roughcut" --show
```
選び直したあとは `finish.py` で書き出してください（演出プランと Premiere 用XMLを書き換えます）。

#### 設定（`template.toml` の `[multicam]`）
| 項目 | 初期値 | 意味 |
|---|---|---|
| `auto` | `true` | 演出プランを作るときに自動で選ぶ（`false` で自動では切り替えない。画面の表で手動では選べます） |
| `ai` | `false` | `true` にすると、AIが「Claude APIで自動」のとき、演出プランを作るたびに Claude で選ぶ |
| `min_shot` | `3.0` | 1つのカメラを続けて映す最短の秒数 |
| `silence` | `4.0` | この秒数以上だれも喋っていない所を手元カメラにする |
| `words` | 「ここを」など | この言葉を含む発言を手元カメラにする |
| `background` | `"blur"` | 縦横の比率が違うとき：`"blur"`＝ぼかした背景 / `"black"`＝黒 |
| `min_confidence` | `6.0` | 音声の同期の信頼度（荒編集のログに出ます）がこれより低いときは、自動では切り替えない |

- ズーム（演出の「ズーム」）は正面カメラの場面だけにかかります
- 確認用テスト：`python tests/test_multicam.py`（`tests/smoke_test.py` からも呼ばれます）

### 話者の色分け（実験的な機能）
屋外企画など、何人かで話している動画で、**発言ごとに「だれが話しているか」を推定して、完成動画の字幕を人ごとの色にします**。実験的な機能なので、最初は使われません（使ったときだけ有効になります）。

- 声の高さと響きの違いで、似た声の発言をグループに分けています。重いAIライブラリは使わないので、追加のインストールは要りません（音声を少しずつ読むので、3時間の素材でもメモリをあまり使わず、数分ほどで終わります）
- 声が似ている人どうし（同じくらいの年代の同性など）や、大きな雑音・BGMが入っている場面は、まちがえやすいです。下の画面で確認・手直ししてください

#### 画面（GUI）で使う
1. 「確認・仕上げ」タブの **「話者の色分け（実験的）」** を押します
2. **話している人数**を選んで（分かっているときは人数を選ぶと正確です。「自動で推定」もできます）、**「話者を推定する」** を押します
3. 左の「話者」の表で、**名前をダブルクリックして変えます**（例: 話者1 → たろう）。いちばん多く話している人が「話者1」で、ふつうの字幕の色になります
4. 右の表で、まちがっている発言を選んで（複数選べます）、下の **「選んだ発言を: 1 たろう / 2 はなこ」** のボタンか、**数字キー 1〜9** で直します。行をクリックすると、その場面を再生します
   - **黄色の行**は、推定の自信が低い発言です。「自信の低い発言だけ表示」で、それだけを確認できます
   - 声が聞き分けにくい人が後から加わったときは、「話者を追加」で人を増やせます
5. 下のチェックを選んで **「保存」** を押します
   - **完成動画の字幕を、話者ごとの色にする**（初期状態はオン）
   - **Premiere用の字幕（SRT）の頭に話者名を入れる**（例: `たろう：こんにちは`）。オンにして保存すると、`○○_字幕.srt` を書き直します
6. 「完成動画を書き出す」（または「最初の60秒を試し書き出し」）で、色分けされた字幕が入ります

もう一度「話者を推定する」を押しても、手で直した発言と名前はそのまま残ります。

#### コマンドで使う
```powershell
# 荒編集と一緒に推定する（人数を指定。省略すると自動で推定）
python roughcut.py C0001.MP4 C0002.MP4 --mode outdoor --speakers 3

# 荒編集のあとから推定する・名前を付ける・SRTに名前を入れる
python speakers.py "D:\撮影\屋外_roughcut" --num 3
python speakers.py "D:\撮影\屋外_roughcut" --no-detect --names "たろう、はなこ、じろう" --srt-names on

# 色分けをやめる（推定の結果は残ります）
python speakers.py "D:\撮影\屋外_roughcut" --no-detect --off
```
結果は `○○_roughcut` フォルダの `speakers.json` に保存されます。文字起こしをやり直して発言の区切りが変わったときは、古い推定は使わないので、もう一度推定してください。

#### 色を変える（テンプレート）
`template.toml` の `[speakers]` で決めます。

| 項目 | 内容 |
|---|---|
| `colors` | 1人目・2人目・3人目…の字幕の色（人数が多いときは最初の色に戻ります） |
| `outline_colors` | 字幕の縁取りの色（人ごと） |
| `caption_name` | `true` にすると、完成動画の字幕にも名前を出します（例: `たろう：こんにちは`） |
| `srt_name_format` | 名前の書き方。`{name}` が名前に置きかわります（初期値: `{name}：`） |

古いテンプレートに `[speakers]` がない場合は、初期の色（白・黄・水色・ピンク・緑・紫）を使います。

- 確認用のテスト：`python tests/test_speakers.py`（2種類・3種類の合成した声で確かめます。`tests/smoke_test.py` からも呼ばれます）

### 声と映像の補正（聞き取りやすい声・明るさと色・手ブレ補正）
完成動画の書き出し（仕上げ）のときに、本編の声と映像を自動で整えます。オープニング・エンディングの動画にはかけません。

**声を聞き取りやすくする（初期設定で使います）**
- 低音カット（エアコンや車の「ゴー」という低い音）→ ノイズ除去（「サー」という音）→ サ行の刺さりを抑える → 声の大きさのばらつきをならす、の順に処理します
- ノイズ除去は、素材の静かな所の音量を調べて、その大きさの音を減らします
- 屋外企画では、風切り音（「ボボボ」という音）対策として、低音を強めにカットします
- 処理で音がわずかに遅れる分は自動で取り除くので、口の動きと声はずれません
- 音楽（MV）など、声以外が主役の動画では、テンプレートの `[audio_clean]` で `enabled = false` にしてください

**明るさ・色（初期設定では使いません）**
- 自動補正：素材ごとに何枚かの画面を調べて、暗すぎる・色かぶり（青っぽい・黄色っぽい）を**控えめに**直します。動画の途中で色が変わったり、ちらついたりしません
- LUT：Premiere などで使う `.cube` ファイルをテンプレートのフォルダに置き、`[color]` の `lut` に書くと、本編に当たります（`lut_strength` でかかり具合を調整）
- 明るさ・コントラスト・鮮やかさ・色温度も、`[color]` で手で調整できます

**手ブレ補正（屋外企画だけ、初期設定で使います）**
- 歩き撮りなどの揺れをおさえます。揺れを消すために、画面が少し拡大されます
- FFmpeg に vidstab が入っていれば vidstab（きれい）、なければ deshake を使います（winget で入れる Gyan 版の FFmpeg には、ふつう vidstab が入っています。`python enhance.py check` で確認できます）
- 手ブレの解析は書き出しと同時に裏で進めますが、書き出しの時間は長くなります（目安：使わないときの1.5〜2倍）

**切り替え方**
- 画面：「作成」タブの「詳細設定 ▸」を開くと「声と映像の補正」の行があります。「おまかせ」（テンプレートと撮影ジャンルに合わせる）／「使う」／「使わない」を選べます。選んだ内容は次回も残ります
- 「色の見本…」ボタン：1つ目の素材の真ん中の場面で、色の補正の前と後を並べて表示します
- コマンド：`python finish.py 出力フォルダ --audio-clean off --color on --stabilize on`（それぞれ `auto` / `on` / `off`）
- テンプレート（`template.toml` の最後）：
  ```toml
  [audio_clean]
  enabled = true        # false で声の処理をしない
  strength = 1.0        # 0.5=控えめ / 1.0=ふつう / 1.5=強め
  wind = "auto"         # 風切り音対策（"auto" = 屋外企画だけ）
  [color]
  auto = false          # true で明るさ・色を自動で少し整える
  lut = ""              # 例: "luts/channel.cube"
  [stabilize]
  enabled = "auto"      # "auto" = 屋外企画だけ / true / false
  ```
- どの補正が使われるかの確認：`python enhance.py check --mode outdoor`

**2台目カメラ（スマホなど）の色を本編に寄せる**
- 「確認・仕上げ」タブの「2台目の色合わせ」ボタン（コマンドなら `python enhance.py cam2 出力フォルダ`）で、`cam2_色合わせ.cube` を結果のフォルダに作ります。2台が同時に撮っている場面を比べて、色の傾向を本編に合わせます
- Premiere Pro では、V2（2台目）のクリップを選んで「Lumetri カラー」→「基本補正」→「入力LUT」の「参照…」でこのファイルを選びます

**時間とメモリ**
- 声の処理は、3時間の素材でも数分です。全体を一度にメモリに読み込まないので、長い素材でもメモリは増えません
- 色の補正は1枚の LUT にまとめてかけるので、書き出しの時間はほとんど増えません
- 確認用テスト：`python tests/test_enhance.py`（`tests/smoke_test.py` からも呼ばれます）

### 工作の作業シーンを自動で早送り
工作モード（`--mode craft`）で残した「喋っていない作業の場面」を、仕上げのときに自動で早送りにします。
- **速さは長さで決まります**：短い作業は 2倍、長い作業ほど速く（最大 8倍）。とても長い作業（乾かす・待つなど、4分以上で 8倍でも長すぎるもの）は「タイムラプス」（最大 30倍）になります。6秒より短い作業はそのままの速さです
- **音**：早送り中は作業の音を消して、BGM だけが流れます。字幕も出しません
- **画面の隅に「▶▶ ×4」**のような印が出ます（タイムラプスは「タイムラプス ×20」）
- 字幕・テロップ・章タイトルのカード・BGM・チャプター（概要欄用）・サムネイル案は、早送りで短くなったあとの時刻に合わせます
- **AIの演出プラン**でも、作業ごとに速さを変えたり（大事な手元は 2〜3倍など）、早送りをやめたり、独り言だけの長い作業を新しく早送りにしたりします。claude.ai に貼り付けて使う場合も、プロンプトに作業の場面が入ります

画面（GUI）では（工作モードの結果を開いたときに表示されます）：
- 「確認・仕上げ」→「② 演出の確認」→**「早送り」**の表で、作業ごとに「使う」のチェックと「速さ」（×2〜×8、タイムラプス）を選べます。「完成での長さ」がその場で変わります
- 行をクリックすると、**その速さで**再生して確かめられます
- 自動では早送りにしなかった短い作業も、チェックを付ければ早送りにできます
- **「Premiere用XML（早送り入り）」**ボタンで、Premiere 用の XML（`○○_早送り入り.xml`）を作ります。早送りのクリップには速度が付き、音は無効になっています。早送りの場所には「早送り ×4」の印（マーカー）も付きます。完成動画の書き出しでも自動で作ります（いつもの `○○_荒編集.xml` は今まで通り、速度なし）

コマンドでは：
```bat
python speedup.py "D:\撮影\工作_roughcut"          :: 早送りの一覧を表示
python speedup.py "D:\撮影\工作_roughcut" --xml    :: 早送り入りの Premiere 用 XML を作る
```
演出プラン（`plan_used.json`）の `"speedups"` に、元の素材の時刻（秒）と速さが入っています。書き換えて `--plan` で指定すると、その通りに書き出します（`"speedups": []` にすると早送りなし）。

見た目と動きは `template.toml` の `[speedup]` で変えられます：
- `enabled = false` … 自動では早送りにしない
- `target_seconds` … 早送りしたあとの長さの目安（初期値 10秒）、`min_speed` / `max_speed` … 速さのはば
- `audio = "fast"` … 作業の音を消さずに、速くして小さく流す（大きさは `audio_volume_db`）
- `badge = false` … 隅の印を出さない。`badge_text` / `timelapse_text` で文字（`{speed}` が倍率）、`position`・`font`・`size`・`color`・`box_color` で見た目
- 見た目は `python finish.py --template-preview` の最初の静止画（`preview_1.png`）の右下で確認できます

### Bロール（差し込み素材）の自動配置
話している物の写真や、作業のアップの動画などを、**その話をしている所に自動で差し込みます**。

**準備**：本編の動画と同じ場所に `broll` というフォルダを作り、画像・動画を入れます（下のフォルダもOK）。
```
D:\撮影\レビュー\
  C0001.MP4
  broll\
    マキタ_ドリル.jpg      ← ファイル名も手がかりになるので、中身が分かる名前がおすすめ
    穴あけのアップ.mp4
```
- 使えるもの：写真（jpg / png / webp / iPhone の heic など）・動画（mp4 / mov など）。スマホの縦の写真・動画もOK
- 別の場所のフォルダを使うときは、画面の「素材フォルダを選ぶ…」か、コマンドの `--folder` で指定します

**画面で使う**
- 素材フォルダがあれば、「演出プランを作る」のときに、AIが素材を見て（動画は始め・中ごろ・終わりのコマ）、発言と照らし合わせて出す所を決めます
- 「② 演出の確認」→「**Bロール**」で確認・変更できます。行をクリックするとその場面を再生します
  - **使う**：チェックを外すと出しません
  - **出し方**：「全画面」＝画面いっぱい ／「ワイプ」＝画面の隅に小さく（話している人の表情も見せたいとき）
  - **長さ**：「おまかせ」は発言の長さに合わせます（2.5〜7秒）。秒数を入れるとその長さで出します
  - 「素材を発言に割り当てる」：今のフォルダの素材で、AIに決め直してもらいます（テロップなどの手直しは残ります）
  - 「素材を1つ足す…」：画像・動画と、出したい発言を選んで足します
  - 「Premiere用XML（Bロール入り）」：Premiere Pro 用に、荒編集のシーケンスに素材を重ねた `素材名_Bロール入り.xml` を作ります
- 変更は「試し書き出し」「完成動画を書き出す」で動画に入ります

**動画での見え方**
- 写真はゆっくり寄る（引く）動き（Ken Burns）が付きます。縦の写真・動画は、ぼかした背景の上に全体を出します
- 出し入れは少しフェードします。動画の素材の音は使いません（声とBGMはそのまま）
- 字幕・テロップ・ロゴは、Bロールの上に出ます

**コマンドで使う**
```
python broll.py "D:\撮影\レビュー\C0001_roughcut"                      # 素材を発言に割り当てる（演出プランに入る）
python broll.py "D:\撮影\レビュー\C0001_roughcut" --folder "D:\素材\ドリル"  # 素材フォルダを指定
python broll.py "D:\撮影\レビュー\C0001_roughcut" --llm none            # AIを使わず、ファイル名が発言に出てくる所に入れる
python broll.py "D:\撮影\レビュー\C0001_roughcut" --xml-only            # 今のプランで Bロール入りの XML だけ作る
python finish.py "D:\撮影\レビュー\C0001_roughcut" --plan plan_edited.json  # 書き出し
```
- AIを使わないとき（「AIを使わない」「claude.ai に貼り付けて使う」）は、ファイル名の言葉（例: `マキタ_ドリル.jpg` → 「マキタ」「ドリル」）が出てくる発言に入れます
- AIが見た素材の説明は `broll_assets.json` に残り、素材が変わらなければ次から使い回します（料金の節約。見直したいときは `--redescribe`）
- 演出プラン（`plan_used.json` / `plan_edited.json`）では `"broll"` に入ります：`{"file": 素材のパス, "start_id": 発言ID, "end_id": 発言ID, "mode": "full" または "wipe", "sec": 秒数（任意）}`

**見た目の設定**（`template.toml` の `[broll]`）
- `wipe_position`（ワイプの位置。初期値は右上。ロゴと同じ隅のときは反対側に出します）・`wipe_width`（幅）・`wipe_border`（白いふちの太さ）
- `kenburns`（写真を寄せる倍率。`1.0` で動かさない）・`min_sec` / `max_sec`（出す長さの目安）・`fade`
- `auto = false` にすると、「演出プランを作る」のときに自動では入れません（「素材を発言に割り当てる」を押したときだけ）

**Premiere Pro のXML**（`素材名_Bロール入り.xml`）
- 荒編集のシーケンス（2台目カメラ・マーカーも）の上に、全画面の素材のトラックと、ワイプの素材のトラックを足します（2台目カメラが無ければ V2・V3）
- 写真のゆっくりズームは「スケール」のキーフレーム、ワイプは「スケール」と「位置」で入れています。Premiere で開いて位置や大きさを確認してください

### オープニング・エンディングの自動生成
テンプレートの設定から、オープニング（ロゴとチャンネル名が出る3秒ほどの動画）と、エンディング（20秒。チャンネル登録の呼びかけと、YouTube の「終了画面」の要素を置く枠）を自動で作ります。

1. `template.toml` の `[opening]` に `channel_name`（チャンネル名）を書きます。ロゴは `[logo]` の画像（または `[opening]` の `logo`）を使います。ジングルを鳴らしたいときは `sound` に音のファイルを書きます
2. `[ending]` の `message`（呼びかけの文字）や `video_boxes`（動画の枠の数 0〜2）、`music`（エンディングの曲）を好みで変えます
3. 画面の「ツール」→「オープニング・エンディングを作る」（またはコマンド `python graphics.py`）で作って、見た目を確認します。できた動画はテンプレートの `generated` フォルダに入ります
4. 作ったあとに出る画面で **「完成動画の最初にオープニングを付ける」「完成動画の最後にエンディングを付ける」** にチェックを入れると（`template.toml` の `[opening]` と `[ending]` の `enabled = true` と同じ）、完成動画の書き出しで最初と最後に自動で付きます（`[intro]` `[outro]` の `file` に自分で作った動画を書いているときは、そちらが優先です）。設定を変えたときは、書き出しのときに自動で作り直します
5. YouTube に投稿したら、YouTube Studio の「終了画面」で、動画とチャンネル登録の要素を枠の上に置きます。枠の位置（画面に対する%）は `generated/outro_終了画面の枠.json` に書いてあります

- オープニングの分だけ、字幕・チャプター（`final_info.json`）は自動でずれます。試し書き出し（プレビュー）では付けません
- 終了画面は、YouTube の決まりで「動画の最後の5〜20秒」に置けます。`duration` は5〜20秒の間にしてください

### テロップの種類（吹き出し・スペック表・比較表・STEP・場所）
今までの4種類（強調・補足・注意・ツッコミ）に、カードの形のテロップを5種類足しました。AIが演出プランを作るときに、動画の内容に合わせて選びます（解説・レビュー＝スペック表・比較表、工作＝STEP、屋外＝場所カード）。「確認・仕上げ」タブの演出の表でも、種類を選んで文字を書けば使えます。

| 種類 | 文字の書き方（「／」で改行） | 例 |
|---|---|---|
| 吹き出し | ひとこと | `なにこれ！？` |
| スペック表 | 1行目が見出し、2行目からは「項目：値」 | `マキタ DF033D／重さ：1.2kg／価格：9,800円` |
| 比較表 | 「／」で行、「｜」で列。1行目が見出し | `｜A社｜B社／重さ｜1.2kg｜1.5kg／価格｜1万円｜8千円` |
| STEPカード | `STEP 番号 やること`（番号を省くと、動画の中で順に数えます） | `STEP 2 穴をあける` |
| 場所カード | 1行目が場所、2行目は小さく出る補足 | `高尾山 山頂／標高599m` |

- 色・大きさ・位置・出方は `template.toml` の `[telop.bubble]` `[telop.spec]` `[telop.compare]` `[telop.step]` `[telop.place]` で変えられます
- 見た目の確認：「ツール」→「テロップの種類と章の進み具合の見本を作る」（またはコマンド `python graphics.py --samples`）。テンプレートの `generated` フォルダに見本の動画と静止画ができます

### 章の進み具合の表示
画面の上に細いバーを出して、章ごとに区切り、今どこまで進んだかを色で表します。左上には今の章の名前を出します（長い屋外企画などで、見ている人が迷わないように）。

- 「ツール」→「テロップの種類と章の進み具合の見本を作る」のあとに出る画面で **「章の進み具合（画面の上のバー）を出す」** にチェックを入れるか、`template.toml` の `[progress]` で `enabled = true` にすると表示します（初期設定では出ません）
- 章は、荒編集でAIが作ったチャプター（YouTube の概要欄と同じもの）を使います。オープニング・エンディングの間は出ません
- `title_seconds = 5` にすると、章の名前は章の頭の5秒だけ出ます。`title_format = "{n}/{total} {title}"` で「2/5 スペック」のような書き方にもできます
- 上に出るカード型テロップ（STEPカードなど）は、バーと重ならないように少し下に出ます

### テンプレートの編集画面とAIのデザイン案
`template.toml` をメモ帳で書き換えなくても、画面で見た目を作れます。「作成」タブの「見た目テンプレート」の横にボタンが2つあります。

**編集…（見た目テンプレートの編集）**
- 左のタブ（字幕・強調・補足・注意・ツッコミ・章カード・サムネイル）で、**フォント**（このPCに入っている日本語フォントの一覧から選ぶ）、**文字の大きさ**、**色**（ボタンを押すと色を選ぶ画面が出ます）、**縁取りの色と太さ**、テロップの**見せ方**（縁取り / 帯）・**位置**・**画面の端からの距離**・**出かた**を変えられます
- 変えると、右の**見本**がすぐ作り直されます。字幕とテロップ4種・章カード・サムネイル2種を、本番の書き出しと同じ方法（字幕ファイルを FFmpeg で焼き込み）で1コマずつ作るので、仕上がりと同じ見た目です
- **背景**は「サンプル（明るい部屋）」「サンプル（夜・暗い）」のほか、作成タブに入れた素材や「確認・仕上げ」タブで開いている動画の1コマ（何秒目かを指定）、好きな画像・動画も選べます。明るい背景と暗い背景の両方で読みやすいか確かめるのがおすすめです
- **別名で保存…**：`templates/<名前>/` に新しいテンプレートを作ります。BGM・効果音・フォント・ロゴなどのファイルも一緒に複製するので、元のテンプレートはそのまま残ります。保存すると「作成」タブで選ばれた状態になります
- **上書き保存**：今のテンプレートの `template.toml` を書き換えます（前の内容は `template.toml.bak` に残ります）。保存した `template.toml` には、各値の意味をコメントで書いておきます（元のファイルにあった説明のコメントは、この書き方に置き換わります）
- Windows で「このユーザーだけ」に入れたフォントを選んだときは、保存の時にそのフォントをテンプレートの `fonts` フォルダにコピーします（FFmpeg が見つけられないことがあるため）

**AIでデザイン案…（AIにデザイン案を作ってもらう）**
1. 「チャンネルの雰囲気」に、例えば「落ち着いた・ガジェット系。工具や家電のレビューが多い」のように入れます（下の「ことばの例」を押すと追加されます）
2. 「3つの案を作る」を押すと、Claude が**このPCに入っている日本語フォントの中から**、配色・フォント・テロップの見せ方の組み合わせを3つ作ります（1〜2分。料金は1回 十数円〜数十円ほど）
3. 3つの案が横に並びます。上の「見比べる所」（強調・補足・注意・ツッコミ・章カード・サムネイル・全部）を押すと、3案とも同じ所に切り替わるので比べやすくなります
4. 気に入った案の「**この案で保存…**」で新しいテンプレートとして保存します。「**細かく調整する…**」を押すと編集画面で続きを直せます（保存するまで元のテンプレートは変わりません）
- 作成タブのAIが「claude.ai に貼り付けて使う」ならプロンプトのコピー＆貼り付けで、「AIを使わない」なら用意してある5つの案（落ち着いた・ポップ・ガジェット系・ナチュラル・モノトーン）から雰囲気に合うものを3つ出します
- 編集画面の「AIにデザイン案を作ってもらう…」から開くと、編集中の内容と選んでいる背景を元にします

**コマンドで使う場合**（`design.py`）
```powershell
python design.py preview --template templates\default                        # 見本の一覧画像（design_preview.png）
python design.py preview --template templates\default --bg "D:\撮影\C0001.MP4" --at 30   # 自分の素材の30秒目で
python design.py propose --template templates\default --mood "ポップ・かわいい"   # AIに3案（結果は _design_work\proposals）
python design.py propose --template templates\default --mood "ポップ" --llm manual   # claude.ai 用のプロンプトを作る
python design.py propose --template templates\default --mood "ポップ" --answer 返答.json
```
- テロップの `margin_v`（画面の端からの距離）・`margin_h`（左右の端からの距離）を `template.toml` に書けるようになりました。書いていなければ今までどおりです
- テスト：`python tests/test_design.py`（`tests/smoke_test.py` からも呼ばれます）

### 人物の切り抜きサムネイルと、顔を見た場面選び
サムネイル案に、**人物を背景から切り抜いて大きく置き、白いフチを付けたデザイン**（`thumb_○_person.jpg`）が加わります。いつもの3種類（下に文字・上に帯・横に文字）はそのまま作られます。

- **場面の選び方がよくなりました**：顔が大きく写っている・目が開いている・表情がほかの場面と違う（笑顔など）画像を優先します。同じ場面の少しずらした3枚からは、目をつぶっていない1枚を選びます。Claude に選んでもらうときも「顔: 大きく写っている・目が開いている」などの補足を一緒に渡します
- **背景のバリエーション**：人物のデザインの背景は、案1＝ぼかし、案2＝鮮やか、案3＝集中線（初期設定）。ほかに「暗く」「単色」も選べます
- **切り抜いた人物だけの透過PNG**（`cutout_○.png`）も保存するので、Photoshop や Premiere で自分でサムネイルを作るときにも使えます
- 顔が見つからない場面（後ろ姿・物だけ・景色だけ）では、人物のデザインは作らず、いつもの3種類だけになります

**切り抜きのしくみ**：初回に、人物の形を見分けるデータ（約6MB）を自動でダウンロードして使います（以後はダウンロードしません）。ネットにつながらない・ダウンロードできないときは、顔の位置から体の範囲を推定する簡易な方法で切り抜きます（背景が人物と似た色だと、少し粗くなります）。どちらも GPU は使わず、ノートPCで1枚あたり数秒です。OpenCV が入っていないPCでは、自動でいつもの3種類だけになります（`setup.bat` をもう一度実行すると入ります）。

**GUI**：メニューの「ツール」から
- 「人物の切り抜きサムネイルの準備（初回のダウンロード）」… データを先にダウンロードして、使えるか確かめます
- 「人物の切り抜きデザインを画像で試す…」… 好きな写真を選ぶと、背景5種類のデザインを作って並べて見せます（写真と同じ場所の「○○_人物デザイン」フォルダに保存）

**コマンド**：
```
python thumbspro.py --setup                                       # 準備（データのダウンロードと確認）
python thumbspro.py --try "D:\写真\自撮り.jpg" --text "軽すぎ！"     # 好きな画像で試す
```

**設定**（`template.toml` の末尾の `[thumbnail.pro]`）：
| 項目 | 内容 |
|---|---|
| `person` | 人物のデザインを作る（`true` / `false`）。`[thumbnail]` の `layouts` に `"person"` と書いても作れます |
| `face_pick` | 顔を見て場面を選ぶ（`true` / `false`） |
| `backgrounds` | 人物のデザインの背景。案1・案2・案3の順に使います。`blur`=ぼかす / `vivid`=鮮やか / `burst`=集中線 / `dark`=暗く / `color`=単色 |
| `side` | 人物を置く側（`auto`=映っていた側 / `left` / `right`）。文字は反対側に入ります |
| `outline` / `outline_color` | 白いフチの太さ（0でなし）と色 |
| `person_height` / `max_zoom` | 人物の大きさ（画面の高さに対する割合）と、拡大の上限 |
| `burst_color` | 集中線・単色の背景の色（空なら `accent_color`） |
| `other_background` | いつもの3種類も、人物はそのままで背景だけ変える（`none` / `blur` / `vivid` / `dark`） |
| `model` | `auto`=初回に自動ダウンロード / `off`=使わない（顔の位置から推定） |
| `save_cutout` | 切り抜いた人物の透過PNGも保存する |

手動でデータを入れる場合は、`human_segmentation_pphumanseg_2023mar.onnx` をツールのフォルダの `models` フォルダ（または `%LOCALAPPDATA%\AutoVideoEditor\models`）に置いてください。確認用テスト：`python tests/test_thumbspro.py`

### 英語字幕と多言語対応
完成動画の字幕（`○○_完成.srt`）を Claude で英語に翻訳して、`○○_完成.en.srt` を作ります。YouTube の英語のタイトル・概要欄も一緒に訳して、YouTube に「英語字幕」と「英語のタイトル・概要欄（翻訳）」として設定できます。海外の人が見ると、英語のタイトルと字幕が表示されます。

**画面で使う**
1. 完成動画を書き出したあと、「確認・仕上げ」タブの **「英語字幕を作る」** を押します。終わると、日本語と英語を並べた確認画面が出ます
   - AIの欄が「claude.ai に貼り付けて使う」のとき（またはAPIキーがないとき）は、貼り付け画面が出ます。API料金はかかりません
2. 「YouTubeへ」画面で **「英語字幕・英語タイトルも設定する」** にチェックを入れて、「② アップした動画に設定を反映」を押します。翻訳がまだ（またはタイトル・概要欄を直したあと）なら、先に翻訳してから設定します。翻訳には Claude を使います。APIキーがあれば自動で、APIキーがないとき（または AIの欄が「claude.ai に貼り付けて使う」のとき）は貼り付け画面が出ます

**コマンドで使う**
```powershell
python translate.py "D:\撮影\レビュー_roughcut"                  # 英語の字幕とタイトル・概要欄
python translate.py "D:\撮影\レビュー_roughcut" --lang en,ko      # 英語と韓国語
python translate.py "D:\撮影\レビュー_roughcut" --llm manual      # claude.ai に貼り付けて使う
python youtube.py "D:\撮影\レビュー_roughcut" --apply --localize  # YouTube に英語の字幕・タイトル・概要欄も設定
```
`--llm manual` のときは `prompt_translate_en.md` ができるので、中身を claude.ai に貼り付けて、返答を `claude_translate_en.json` として同じフォルダに保存し、もう一度同じコマンドを実行します。

**しくみと気をつけること**
- 字幕の**出る時刻は日本語の字幕と同じ**です。日本語は1文の途中で字幕が切り替わることが多いので、続いている字幕をまとめて文として訳し、英語の長さに合わせて1枚（1行42文字・2行まで）に区切り直します。英語が長くて読み切れないときは、次の字幕が出る直前まで（最大1.5秒）表示を延ばします
- 概要欄のチャプターは、時刻はそのままで見出しだけを訳します
- 訳した内容は保存されます。もう一度押しても Claude は呼ばれません。カットを直して書き出し直したときは、**変わった字幕だけ**を訳し直します。タイトルや概要欄を直したときは、タイトル・概要欄だけを訳し直します
- YouTube に設定するとき、Studio で自分で入れたほかの言語の翻訳は消さずに残します。前にこのツールで入れた英語字幕は、新しいものに差し替えます
- 動画には日本語の字幕が焼き込まれているので、視聴者が英語字幕をオンにすると、日本語の字幕の上に英語の字幕が重なって表示されます（YouTube の字幕は視聴者がドラッグで動かせます）
- 料金の目安：30分の動画で数十円です（実行後に表示されます）

**ほかの言語を足す**：テンプレートの `template.toml` の `[translate]` で、作る言語を変えられます（YouTube の言語コード）。
```toml
[translate]
languages = ["en", "ko", "zh-Hans"]   # 英語・韓国語・中国語（簡体字）

[translate.ko]                        # 言語ごとの読みやすさ（書かなければ、言語に合った値を使います）
max_line = 18                         # 1行の最大文字数
reading_speed = 9                     # 1秒に読める文字数の目安
```

| できるファイル | 内容 |
|---|---|
| `○○_完成.en.srt` | 英語の字幕（Premiere や YouTube Studio にもそのまま読み込めます） |
| `translations.json` | 英語のタイトル・概要欄と、翻訳の状態 |
| `translate_cache.json` | 訳した字幕の控え（書き出し直したときに、訳し直さずに使います） |
| `prompt_translate_en.md` / `claude_translate_en.json` | claude.ai に貼り付けて使うときのプロンプトと返答 |

テスト：`python tests/test_i18n.py`（`tests/smoke_test.py` からも呼ばれます）

### 縦型ショートの自動生成
本編の中から、YouTubeショートに向いた所（**30〜60秒・最初の数秒に「つかみ」がある所**）を選んで、縦型（1080x1920）の動画を最大3本作ります。

**画面で使う**
1. 「確認・仕上げ」タブで結果を開き、下の「**ショートを作る**」を押します（横の「最大 3 本」で本数を変えられます）
2. できあがると一覧が出ます。「▶ 再生」で確認、「コピー」でタイトルと説明文（`#shorts` 付き）をコピーして、YouTube Studio に貼り付けます
3. あとから見るときは「ショートを見る」、保存場所は一覧の「フォルダを開く」

区間の選び方は「作成」タブの AI の欄に従います。
- **Claude APIで自動**：Claude が文字起こしを読んで、つかみのある所から始まり、オチまで入る区間を選び、タイトル・説明文・ハッシュタグも考えます
- **claude.ai に貼り付けて使う**：いつもの貼り付け画面が出ます（API料金なし）
- **AIを使わない**（または APIキーがないとき。「Claude APIで自動」のままキーがないときは、見どころから選ぶか確認が出ます）：見どころ（緑の行）・強調テロップ・ズームの所から始まる区間を自動で選びます

**コマンドで使う**
```powershell
python shorts.py "D:\撮影\レビュー_roughcut"                 # Claudeが区間を選んで最大3本
python shorts.py "D:\撮影\レビュー_roughcut" --count 1       # 1本だけ
python shorts.py "D:\撮影\レビュー_roughcut" --llm none      # AIなし（見どころの周りから）
python shorts.py "D:\撮影\レビュー_roughcut" --llm manual    # claude.ai 用のプロンプト（shorts\prompt_shorts.md）を作る
python shorts.py "D:\撮影\レビュー_roughcut" --picks claude_shorts.json   # claude.ai の返答で作る
```

**映像の作り方**
- 人の**顔を追いかけて**縦長に切り抜きます。顔がない場面は**動きの多い所**、それもなければ**中央**を映します
- カメラが急に動かないように、少しの動きは追いかけず、なめらかに動かします。カットのつなぎ目では、次の場面の位置に切り替わります
- 縦型向けに**大きな字幕を中央寄り**に、**上部にタイトルの帯**を入れます。演出プランの強調テロップも入ります
- 素材がもともと縦長（スマホの縦撮り）なら、幅いっぱいで使います

**見た目を変える**：テンプレートの `template.toml` の `[shorts]` で変えられます（例: `layout = "blur"` にすると、切り抜かずに横長の映像を真ん中に置き、上下をぼかした映像で埋めます。帯の色・字幕の大きさと位置・追いかけるなめらかさ・本数・長さなど）。

**できるもの**（`素材名_roughcut\shorts` フォルダ）
| ファイル | 内容 |
|---|---|
| `short_1.mp4` 〜 `short_3.mp4` | 縦型ショート（1080x1920） |
| `short_1.jpg` など | 一覧に出す小さな画像 |
| `shorts.json` | 各ショートのタイトル・説明文（`#shorts` 付き）・本編のどこから切り出したか |
| `prompt_shorts.md` / `claude_shorts.json` | claude.ai に貼り付けて使う場合のプロンプトと返答 |

- 顔の検出には OpenCV（`opencv-python-headless`）を使います。`setup.bat` をもう一度実行すると入ります
- 長い素材（3時間など）でも、切り出す区間だけを読み込むので、メモリはあまり使いません
- 確認用テスト：`python tests/test_shorts.py`（`tests/smoke_test.py` からも呼ばれます）

### 公開後の分析（視聴維持率・コメント・告知文）
YouTube に公開した動画の「どこで見るのをやめた人が多かったか」を調べて、次の動画の編集に生かします。画面の **「分析」タブ**（または「確認・仕上げ」タブの「公開後の分析」ボタン）で使います。

**最初の1回だけの準備**
1. [Google Cloud Console](https://console.cloud.google.com/) の「APIとサービス」→「ライブラリ」で **YouTube Analytics API** を検索して「有効にする」（YouTube Data API v3 と同じプロジェクトで）
2. 「分析」タブの **「Googleと連携し直す」** を押して、ブラウザで**すべての項目を許可**します（視聴維持率を読む許可 `yt-analytics.readonly` が増えたため。前から連携している人も1回だけ必要です）
   - 「YouTubeへ」画面の連携の準備（client_secret.json）がまだの人は、先に「5-3. YouTubeへの投稿」の準備をしてください
   - Google の画面で項目のチェックを外すと、外した許可は使えません（YouTube の項目を外すと連携できず、分析の項目だけ外すとアップロード・設定は使えますが分析は使えません）。そのときは、もう一度「Googleと連携し直す」を押して、すべてにチェックを入れてください
   - 「YouTube Analytics API が有効になっていません」と出たときは、1. の「有効にする」を押してから数分待って、もう一度試してください

**① 視聴維持率**：「視聴維持率を分析」を押すと、YouTube から「動画のどの時刻に、何%の人がまだ見ていたか」を取り出します
- いつもより大きく視聴者が減った場面（最大5か所）と、巻き戻して見返された場面を自動で見つけて、グラフに番号を付けます
- その場面の**元の発言・テロップ・章・画面**（完成動画から取り出した静止画）をそろえて、Claude が「考えられる原因」と「次の改善案」を書きます
- 結果は `analytics\report.md`（グラフ・場面の画像つき）にも保存されます
- 公開してから2〜3日たって、ある程度見られてからでないとデータが出ません（非公開・限定公開の動画も出ません）
- 動画IDは「YouTubeへ」で設定した動画を自動で使います。違う動画を分析したいときは「動画ID」欄に入れてください

**④ チャンネルの傾向**：分析した動画の結果は、チャンネル全体の `channel_insights.json`（`%APPDATA%\ai-roughcut\`）にたまっていきます
- 「傾向をまとめ直す」で、何本もの動画でくり返し起きていることを Claude がまとめます
- **「この傾向を、次の荒編集（カット判定）と演出プランの AI に伝える」** にチェックが入っていると、次からのカット判定・演出プランの AI への指示に「このチャンネルの過去の動画の分析から（参考）」として足されます（ジャンルごとに使い分けます。チェックを外すと今までどおり）

**② コメント**：「コメントを要約して返信案を作る」で、好評・要望・質問・不満の要約と、返信した方がよいコメントへの返信案を作ります
- 返信案は表でダブルクリックして直せます。「選んだ返信をコピー」で Studio に貼るか、「選んだ返信を投稿…」で確認してから投稿できます（勝手に投稿することはありません）
- 宣伝・荒らしなど、返信しない方がよいコメントも教えてくれます
- ほかの人のコメントのデータは、YouTube の規約に合わせて**30日たつと自動で消します**

**③ 告知文**：「告知文を作る」で、X（旧Twitter）の投稿案3つ・Instagram の投稿文とハッシュタグ・ショート動画のタイトルと説明文（見どころ★ごと、本編へのリンクと #Shorts つき）を作ります。X は日本語140字（URL込み）を超えると赤字で知らせます

**⑤ API審査の申請**：「APIで動画ごとアップロード」を使えるようにする Google の審査（audit）の申請手順と、申請フォームに書く文の下書き（英語の文例つき）を [`docs/youtube_audit_draft.md`](docs/youtube_audit_draft.md) にまとめました。審査をしなくても、今までの「Studio にアップ → 設定を反映」の流れは使えます

AIの欄が「claude.ai に貼り付けて使う」なら貼り付け画面が出ます（API料金なし）。「AIを使わない」なら、数字だけのレポートと決まった形の告知文を作ります。

コマンドで使う場合：
```powershell
python analytics.py --login                                  # 分析の許可も含めて連携し直す（最初の1回）
python analytics.py "D:\撮影\レビュー_roughcut" --retention    # 視聴維持率の分析
python analytics.py "D:\撮影\レビュー_roughcut" --comments     # コメントの要約と返信案
python analytics.py "D:\撮影\レビュー_roughcut" --promo        # 告知文
python analytics.py "D:\撮影\レビュー_roughcut" --all          # 3つまとめて
python analytics.py --retention --video-id XXXXXXXXXXX       # このツールで作っていない動画も（発言との対応はなし）
python analytics.py --trends                                 # チャンネルの傾向をまとめ直す
python analytics.py --use-in-prompts off                     # 傾向を次のAIに伝えない
python analytics.py --status                                 # 連携の状態と、次のAIに足す指示を表示
python analytics.py --purge                                  # 保存した分析データを消す
```
作られるファイル（`素材名_roughcut\analytics` フォルダ）：`report.md`・`retention.png`・`frames\`（視聴維持率）、`comments.md`（コメント）、`promo.md`（告知文）、それぞれの `.json`

### MVモード（ビートに合わせたカット）
曲と撮影素材を入れるだけで、**曲の拍（ビート）に合わせてカットをつないだMVのラフ**を作ります。サークルのMVの「たたき台」作りや、ショート用のサビだけ動画に使えます。

**画面で使う**：「MV」タブを開きます。
1. **曲**：曲のファイル（mp3・wav・m4a など）をドラッグ＆ドロップするか、「曲を選ぶ…」で選びます
2. **映像素材**：動画ファイル、または動画の入った**フォルダ**をドラッグ＆ドロップします（フォルダの中はまとめて読みます。縦長のスマホ動画・音声のない動画も使えます）
3. **作り方**を選びます
   - **素材の選び方**
     - **おまかせ（動き・明るさで自動）**：動きの量・明るさ・くっきり度で自動で選びます。静かな所は動きの少ない絵、サビは動きの多い絵を使います。暗すぎる絵は使いません
     - **AIが選ぶ（Claude）**：Claude が素材の代表フレーム（最大36枚）を見て、「曲の雰囲気」のメモに合う場面と順番を考えます（APIキーが必要。料金は1回あたり数円〜数十円が目安）
     - **撮った順**：撮影した順番（分からなければファイル名の順）に、曲の頭から最後まで並べます。ライブやイベントの記録に向いています
   - **曲の雰囲気**：「夏の終わり・青春・疾走感のあるロック」のように書きます（「AIが選ぶ」のときに使います）
   - **カットの速さ**：ふつう（サビは2拍・Aメロは1小節・イントロは2小節ごと）／細かめ／ゆったり。サビの直前の1小節は1拍ずつ切り替えて盛り上げます
   - **画面**：横長・縦長（ショート）・正方形。素材の形が違うときは、画面いっぱいになるように切り取ります
   - **使う範囲**：曲全体、または**サビだけ**（一番盛り上がるサビを、1小節前から）
   - **テンポ**：ふつうは「自動」のままで大丈夫です。テンポがずれて見えるときだけ、BPMの数字を入れます
4. 「**曲を解析**」を押すと、テンポとサビの位置がグラフに出ます（数秒で終わります）。グラフの色は、オレンジ＝サビ、水色＝Aメロ、紫＝Bメロ、灰色＝イントロ・アウトロです
5. 「**試しに20秒**」で雰囲気を確かめてから、「**MVラフを作る**」を押します。グラフの下の色の帯がカット（色＝素材）です。帯にマウスを乗せると、どの素材のどこを使ったかが出ます

**できるもの**（曲と同じ場所の「曲名_mv」フォルダ）
| ファイル | 内容 |
|---|---|
| `曲名_MVラフ.mp4` | MVのラフ（曲の音つき）。試し書き出しは `曲名_MVラフ_試し.mp4` |
| `曲名_MV.xml` | Premiere用のシーケンス。素材は並べた状態で、**拍の位置にマーカー**（小節の頭は「12小節」、サビの頭は「【サビ】」）が入っています |
| `mv_plan.json` | カットの一覧（どの素材のどこを使ったか・理由） |
| `mv_song.json` / `mv_clips.json` | 曲と素材の解析結果（2回目からは使い回すので速くなります） |
| `mv_frames\` | AIに見せた代表フレーム |

Premiere では「ファイル → 読み込み」で `曲名_MV.xml` を選びます。カットの位置を拍のマーカーに合わせて直したり、素材を差し替えたりして仕上げてください。

**コマンドで使う**
```powershell
python mv.py 曲.mp3 素材フォルダ                                   # おまかせ
python mv.py 曲.mp3 素材フォルダ --order ai --note "夏・青春・疾走感"   # AIが選ぶ（Claude）
python mv.py 曲.mp3 A.mp4 B.mp4 --order files                       # 撮った順
python mv.py 曲.mp3 素材フォルダ --part sabi --size 1080x1920         # サビだけ・縦長
python mv.py 曲.mp3 素材フォルダ --preview 20                         # 最初の20秒だけ試す
python mv.py 曲.mp3 --analyze-only                                   # 曲の解析だけ
```
- そのほかのオプション：`--pace fast|normal|slow`（カットの速さ）、`--bpm 128`（テンポの指定）、`--beats-per-bar 3`（3拍子）、`--fps 24`、`--fit contain`（黒帯で全体を入れる）、`--markers bars|sections`（マーカーを小節ごと・区間だけにする）、`--no-render`（XMLだけ作る）、`--seed 2`（おまかせの組み合わせを変える）
- 見た目テンプレートの `[mv]` で、画面の大きさ・カットの速さ・マーカーの細かさなどの初期値を変えられます。画質とエンコーダは `[video]` の `quality` と `encoder` を使います
- 長い素材（3時間など）も使えます。15分より長い素材は、速く読むために一部の絵（キーフレーム）だけ調べます。メモリはほとんど使いません
- テンポ・拍・サビの検出は、ドラムやベースがはっきりした曲が得意です。アカペラ・弾き語りなど拍が分かりにくい曲は、`テンポ` を手で入れると安定します。拍子は4拍子として扱います（3拍子は `--beats-per-bar 3`）
- テスト：`python tests/test_mv.py`（`tests/smoke_test.py` からも呼ばれます）

### 途中からの再開（止まっても最初からやり直さない）
- **文字起こし**：10分ずつ区切って文字起こしし、区切りごとに `transcript_partial.jsonl` に途中保存します。PCが止まったり「中止」を押したりしても、もう一度同じ素材で実行すれば、**終わった所の続きから**再開します（分割ファイルは、終わったファイルをそのまま使います）。一度に読み込む音声も10分ずつなので、3時間の素材でもメモリをあまり使いません
- 最初からやり直したいときは `--retranscribe` を付けます（途中保存も消します）
- **仕上げの書き出し**：本編は数十カットずつのパーツ（`work\part_○○.mkv`）に分けて書き出しています。途中で止まったあとにもう一度書き出すと、**最後まで書けたパーツはそのまま使い回し**、残りだけを書き出します（カットや演出を変えた所のパーツだけ作り直します）。書き出しが終わると `work` フォルダは消えます

### まとめて処理（寝ている間に何本も）
- 画面の **「まとめて処理」タブ**で、複数の動画を順番待ちに入れて、上から1本ずつ処理します
  - 「作成」タブで素材を入れて **「順番待ちに入れる」**（右の ▾ でメニューが開きます） →「荒編集だけ」「完成動画まで」「サムネイルまで」から選ぶと、今の素材（分割ファイル・2台目カメラも）と設定のまま追加されます
  - 「まとめて処理」タブに動画をドラッグ＆ドロップすると、1本ずつ別の動画として追加されます（設定は「作成」タブのもの）
  - **「順番に処理を始める」** を押してから寝れば、朝には一覧で結果を確認できます（完了・エラー・かかった時間・Claudeの料金）。一覧をダブルクリックすると「確認・仕上げ」タブで開きます
- 処理中は **PCがスリープしません**（ノートPCは電源につないでおいてください）。「全部終わったらPCの電源を切る」にチェックを入れると、最後の動画の2分後に電源を切ります（取り消すときは Windowsキー＋R で `shutdown /a`）
- 1本がエラーになっても、次の動画に進みます。エラーの理由は一覧に出ます。直したら「もう一度やる」で続きから進めます
- 途中で止まった動画（「中断（次は続きから）」）は、もう一度「順番に処理を始める」を押すと、終わった工程を飛ばして続きから進めます
- AIは「Claude APIで自動」か「AIを使わない」で使います（「claude.ai に貼り付けて使う」は、貼り付ける人がいないので使えません）
- 画面で演出を手直ししてある（`plan_edited.json` がある）動画は、その演出で書き出します
- 動画ごとのログは、出力フォルダの `batch_log.txt` に残ります。順番待ちの一覧は `%APPDATA%\AutoVideoEditor\queue.json` にあるので、ツールを更新しても消えません
- コマンドでも使えます：
```
python batch.py add 動画1.mp4 動画2.mp4 --goal finish           # 2本を別々に追加（完成動画まで）
python batch.py add C0001.MP4 C0002.MP4 --join --mode outdoor   # 分割ファイルを1本として追加
python batch.py add 工作.mp4 --cam2 スマホ.mp4 --mode craft --goal thumbs
python batch.py run              # 順番に処理（--shutdown で終わったら電源を切る）
python batch.py list             # 一覧と結果
python batch.py retry <id>       # もう一度（--from-start で荒編集から）
```

### 最新版に更新
- 画面の **「ヘルプ」→「最新版に更新…」** で、GitHub（MiyamaeLing/AutoVideoEditor の main）から最新版をダウンロードして上書きします。終わったら「今すぐ開き直しますか？」で開き直すと新しい版になります
- **消さないもの**：自分で直したテンプレートのファイル（`template.toml`・BGM・効果音・フォントなど）、自分で作ったテンプレート、`.venv`、自分で足した拡張（`gui_ext_○○.py`）、画面の設定、順番待ちの一覧、YouTube連携。更新でファイルを消すことはありません
  - 自分で直したテンプレートのファイルは残し、新しい版の中身は `_update_backup\日時\_新しい版（…）` に置きます（見比べたいとき用）。直していないテンプレートのファイルは新しい版になります（`setup.bat` を実行したときの状態を覚えておき、それと比べて判断します）
- 必要なライブラリが変わったときは、自動で追加します（setup の「ライブラリ」の段階と同じことをします）
- 上書きする前のファイルは `_update_backup` に残すので、うまく動かなくなったら `python update.py --rollback` で元に戻せます
- **起動したときに新しい版があれば**、画面の下に黄色いお知らせが出ます（「更新する」で更新）。お知らせが要らないときは「ヘルプ」→「起動時に新しい版を確認する」のチェックを外します
- git で管理しているフォルダ（`git clone` したもの）は自動更新しません。`git pull` で更新してください
- コマンドでも使えます：`python update.py --check`（確認だけ）/ `python update.py`（更新）/ `python update.py --zip ダウンロードしたzip`（ネットにつながらないPCで）

### これまでの細かい改善

#### チャプターの位置を「発言」で覚える
- AIが作ったチャプターは、その章が始まる**発言**で覚えるようになりました。「カットの変更を反映」でカットを変えても、テンプレートの `fps` を素材と違う値（例: `"30"`）にしても、章タイトルのカード・`final_info.json`・YouTube の概要欄のチャプターが、見出しどおりの位置に出ます
- claude.ai に貼り付けて使う場合は、`prompt_youtube.md` を作ったときの「行番号と発言の対応」を `meta_lines.json` に保存します。あとから `--decisions` でカットを入れて `--meta` で返答を渡しても、チャプターがずれません

#### YouTube画面の「動画ID」欄と「AIの案に戻す」
- 完成動画を書き出し直すと、「YouTubeへ」画面の概要欄のチャプターが、今の動画に合わせて自動で更新されます。タイトル・タグなど自分で直した欄はそのまま引き継ぎます。前に設定した動画IDは使わず、新しくアップした動画を探します（画面の上に黄色いお知らせが出ます）
- **動画ID（空なら自動で探す）**：ふだんは空のままで大丈夫です。決まった動画に設定したいときは、Studio の動画のURL（`studio.youtube.com/video/○○○/edit`）の ○○○ を入れます
- 「② アップした動画に設定を反映」で動画が見つからなかったとき（Studio でタイトルを先に変えた場合など）は、**最近アップロードした動画の一覧**が出るので、選ぶだけで設定できます
- **AIの案に戻す**：画面で直した内容を捨てて、AIの案と今の完成動画のチャプターから作り直します

#### 演出の手直しが消えない
- 「② 演出の確認」の表で直した内容（テロップの文字・チェック・種類・効果音・ズーム）は `plan_edited.json` に保存されます。「カットの変更を反映」をしても、ツールを開き直しても消えません。チェックを外した行も、外したまま残ります
- 「演出プランを作る」でプランを作り直したときは、前の手直しは使わず、新しいプランを表示します（コマンドで `finish.py` が新しいプランを作ったときも同じです）
- 表（テロップ・ズーム・BGM・カメラ・Bロール・早送り）を直したあと、ボタンを押さずに「別の結果を開く…」で切り替えたときや、ツールを閉じたときも、自動で `plan_edited.json` に保存します

#### 書き出し後のサムネイル案もAIが選ぶ
- 画面の「最初の60秒を試し書き出し」「完成動画を書き出す」でも、作成タブのAIが「Claude APIで自動」なら、書き出しのあとに Claude が画像を見てサムネイル案を選びます。コマンドでは `finish.py` の `--llm` に従います（APIキーがないときは、自動で場面を選びます）
- 「完成まで一気に作る」を「claude.ai に貼り付けて使う」で使うと、演出プランを貼り付けたあと、そのまま完成動画の書き出しまで進みます

#### 中止・エラー・処理中の表示
- 「中止」を押したときやツールを閉じたときは、裏で動いている FFmpeg も一緒に止めます。中止はエラー扱いしません
- エラーで止まったときは、ダイアログに**原因**と、**画面でどうすればよいか**（例: 「APIキーを設定…」で入れる、「claude.ai に貼り付けて使う」を選ぶ）を表示します
- 処理中は、ほかの処理のボタンが灰色になって押せなくなります（拡張機能のボタン・「ツール」メニューの項目・「別の結果を開く…」も同じ。素材検索・まとめて処理から結果を開くこともできません。処理が終わったときの続き（演出の手直しを消す・できた動画を開くなど）が、別の結果に向かないようにするためです）
- AIを「Claude APIで自動」にしていてAPIキーがないときは、「演出プランを作る」「サムネイル案を作る」「完成まで一気に作る」を押した時点でお知らせします

#### ドラッグ＆ドロップの並び順（roughcut_drop.bat）
- 複数のファイルを `roughcut_drop.bat` にまとめてドロップしたとき、どのファイルをつかんでいても、**名前の順**（C0001 → C0002 → C0003）に並べてから1本につなぎます
- 「Q&A.mp4」のように `&` を含む名前のファイルも、そのまま読み込めます

- 章タイトルのカードを避けてテロップを後ろにずらしたときは、効果音も一緒にずらします（出さないテロップの効果音は鳴らしません）

#### 機能を合わせたあとの直し
- **公開後の分析と早送り**：早送りを入れた動画でも、離脱が多かった場面と発言・テロップの時刻が合うようになりました（早送りで縮めた分を計算に入れます。手直しした早送り `plan_edited.json` も使います）
- **日本語のフォルダ**：Windows のユーザー名やツールのフォルダに日本語が入っていても、人物の切り抜きのデータと顔検出のデータを読めます

- **ダークモード**：撮り漏れチェックの表・話者の色分けの黄色い行・分析のまとめ・補足の文字が、暗い画面でも読めます

- **APIキーがないとき**：MVの「AIが選ぶ」・カメラの「AIで選び直す」・まとめて処理は Claude API でしか動かないので、その代わりの方法を案内します。ショートは、見どころから選ぶか確認します
- **「色の見本…」**：「明るさ・色」が「おまかせ」で、完成動画に色の補正がかからない設定のときは、見本の画面でそう知らせます
- **順番待ちの一覧**：画面とまとめて処理が同時に一覧を書き換えても、更新が消えたり、止まったりしません
- **困ったときの情報**：GPU の欄の日本語が化けなくなりました。読めない動画があっても、文字コードのエラーで止まらずに「読めませんでした」と出ます

## 困ったとき

- **GPUで動かない**：自動でCPUに切り替わります（その分時間がかかります）。RTX 50シリーズは新しい世代なので、ライブラリ側の対応状況によっては起こる可能性があります。表示されたエラー文を教えてください
- **VRAM不足（out of memory）**：`--batch-size 4` を付けて実行してください
- **スマホ素材だけ映像がずれる**：可変フレームレートが原因のことが多いです。スマホのカメラ設定でフレームレートを固定（30fpsなど）にしてください
- **同期の信頼度が低い**：Premiereで波形を見て確認してください。2台とも、撮り始めに手を1回叩いておくと確実に合います
- **カットが強すぎる／弱すぎる**：`rc_timeline.py` の `PRESETS` の数値で調整できます
- **AIの判定が雑**：`--effort high` を付けると、Claudeがより深く考えます（料金は少し上がります）
- **テロップの文字が四角（□）になる・フォントが違う**：`template.toml` のフォント名が、PCに入っているフォントの名前と一致していません。`fonts` フォルダにフォントファイルを置いてください
- **「作業フォルダを消せませんでした」と出る**：前の書き出しの FFmpeg がまだ動いているか、ほかのアプリが `work` フォルダのファイルを開いています。少し待ってからやり直し、直らなければPCを再起動してください
- **書き出しで「h264_nvenc」のエラー**：テンプレートの `encoder = "libx264"` にすると、GPUを使わずに書き出せます（遅くなります）

## 料金・時間の目安
- 文字起こし：ローカルのGPUで処理するので無料です。時間はGPUの状態で変わりますが、素材の長さよりかなり短く終わる想定です
- サブスク（Claude Code）：追加の料金はかかりません（サブスクの使用量の枠を使います）
- Claude API（`claude-opus-5-5`）：素材30分で数十円、3時間でも百円前後が目安です（仕上げの演出プランも含めて）。実際の料金は実行後に表示されます
- 仕上げの書き出し：カットとズームの反映、焼き込みの2回エンコードします。NVENCを使えば、素材の長さより短い時間で終わる想定です
